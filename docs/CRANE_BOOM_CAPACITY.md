# Горизонтальная стрела: собственный вес и концевой груз

Статус: расчётная модель прототипа **1.4**, issue #36.

## 1. Задача

Пользовательский вопрос отличается от чистого бокового `1 Н` verification case:

> Если ту же модульную конструкцию использовать горизонтально как консольную стрелу, какой максимальный груз можно подвесить на её конце?

Для этого нужен отдельный load case, потому что при горизонтальной ориентации собственный вес самой стрелы действует поперёк её продольной оси и создаёт изгиб даже при нулевом концевом грузе.

## 2. Что меняется относительно вертикальной мачты

Геометрия, жёсткость элементов, материал и выбранный физический межмодульный узел остаются теми же. Меняется ориентация гравитации относительно конструкции.

Вместо фактического поворота всех координат модели в линейной изотропной frame-задаче используется эквивалентная операция: вектор собственного веса поворачивается из вертикального направления в горизонтальную плоскость XY.

Для каждого арматурного member:

```text
A = pi*d²/4
qg = rho*A*g*gamma_g
```

и распределённая нагрузка:

```text
q = qg*e(alpha)
```

где `e(alpha)` — единичный горизонтальный вектор выбранного направления.

## 3. Концевой груз

Пробная масса `m` создаёт расчётную силу:

```text
Pend = m*g*gamma_payload
```

Она прикладывается в том же поперечном направлении и поровну распределяется между тремя узлами конца стрелы.

В этой специальной задаче отключены:

```text
wind
ice
обычная vertical equipment gravity
```

чтобы не смешивать разные сценарии.

## 4. Проверяемые пределы

Каждый trial case проходит существующую frame/connection модель:

```text
Umember <= 1
Ubolt <= 1
lambda_cr >= 1
```

Сводный показатель:

```text
Utotal = max(Umember, Ubolt, 1/lambda_cr)
```

Предел найден, когда следующий больший концевой груз уже не проходит.

Governing mode может быть:

```text
material-strength
local-member-buckling
global-buckling
bolt-connection
boom-self-weight-overlimit
```

Последний вариант означает, что горизонтально ориентированная конструкция не проходит уже от собственного веса арматурных рёбер без дополнительного груза.

## 5. Направления

Из-за 120° rotational symmetry рассматривается сектор:

```text
0 <= alpha < 120°
```

с шагом lateral-capacity grid. Для каждого направления отдельно находится допустимая масса, затем берётся минимальная:

```text
mboom = min_alpha mlimit(alpha)
```

## 6. Поиск массы

Для каждого направления:

1. проверяется `m=0` только с горизонтальным собственным весом;
2. верхняя граница массы увеличивается экспоненциально `1,2,4,8,... кг` до первого FAIL;
3. граница уточняется binary search;
4. сохраняется последняя проходящая масса.

Текущая точность binary search задаётся `CRANE_BOOM_BISECTION_ITERATIONS`.

## 7. Связь с чистым lateral unit-load

Существующий [`LATERAL_CAPACITY_WEATHER_VALIDATION.md`](LATERAL_CAPACITY_WEATHER_VALIDATION.md) решает другую задачу:

```text
F0 = 1 Н transverse
self weight = 0
wind = 0
ice = 0
equipment = 0
```

Из неё получается:

```text
Flim
mideal = Flim/g0
```

`mideal` полезен как чистый structural upper/reference bound, но не учитывает расход несущей способности на собственный вес горизонтальной стрелы.

Новый результат:

```text
craneBoomCapacity.maximumEndPayloadMassKg
```

учитывает self weight арматурных members и потому является более содержательной оценкой горизонтальной компоновки.

Regression требует для типового случая:

```text
mboom < mideal
```

## 8. Что именно учитывается в собственном весе

На текущем этапе в distributed horizontal gravity включается масса арматурных frame members:

```text
rho*A*L
```

Это совпадает с тем self-weight layer, который участвует в production FEM вертикальной мачты.

Масса гаек, болтов и сварочного металла существует в отдельном `assemblyMass`, но пока не возвращается автоматически в FEM self-weight из-за уже задокументированной обратной связи `усилия -> требуемая сварка -> масса -> усилия`.

Следовательно горизонтальная стрела пока также не добавляет fabrication mass метизов/сварки в distributed gravity.

## 9. Что результат НЕ означает

`maximumEndPayloadMassKg` не является паспортной SWL реального крана.

Пока не моделируются:

- динамический коэффициент подъёма;
- рывок, раскачивание и торможение груза;
- трос, блоки, лебёдка и точки их крепления;
- реальный шарнир/поворотный узел стрелы;
- собственная масса метизов и сварки в FEM;
- ветер и обледенение горизонтальной стрелы;
- геометрическая нелинейность/P-Delta;
- initial imperfections;
- fatigue и циклическая работа соединений/сварки;
- нормативные требования к грузоподъёмным механизмам.

Поэтому результат предназначен для инженерного сравнения и предварительной оценки конструкции, а не для разрешения эксплуатации подъёмного устройства.

## 10. Автоматические проверки

`tests/crane-boom-capacity.test.js` проверяет:

- поворот собственного веса в поперечное направление;
- отсутствие ложной вертикальной компоненты при горизонтальном case;
- добавление концевого груза к distributed self weight;
- finite positive boom capacity;
- меньшую capacity относительно pure-tip upper bound;
- рост capacity при увеличении диаметра арматуры;
- корректный вычет уже заданной массы из additional payload.

Focused CI gate issue #36 запускает эти проверки вместе с упрощённой top-mass моделью и диапазоном раскроя `1…48`.
