# Issue #36 — упрощение статической нагрузки и раскроя арматуры

Статус: проектный контракт PR по issue #36.

## Цель

Пользовательский интерфейс должен отвечать на два практических вопроса без дублирующих способов задания одной и той же нагрузки:

1. сколько суммарной массы можно разместить на верхней грани вертикальной мачты и сколько килограммов остаётся до первого расчётного предела;
2. каков поперечный предел нагрузки вершины при использовании конструкции как консольной стрелы.

Поля «дополнительная вертикальная сила» и «дополнительная горизонтальная сила» не должны быть пользовательскими параметрами. Внутренние единичные нагрузки, нужные для verification и нормированных предельных задач, должны передаваться отдельным расчётным API и не попадать обратно в пользовательскую модель параметров.

Эквивалентный объём воды не является отдельным расчётным результатом: при необходимости он непосредственно получается из массы и плотности воды.

## Раскрой арматуры

Количество равных частей закупочного прутка должно поддерживаться во всём диапазоне:

```text
1, 2, 3, …, 48
```

Количество частей остаётся целым положительным числом, а длина одного ребра вычисляется как:

```text
a = Lstock / nparts
```

## Граница модели

Issue #36 упрощает пользовательскую модель нагрузки и терминологию, но не отменяет FEM, собственный вес, ветер, лёд, проверку соединительного узла, local/global buckling и существующие коэффициенты надёжности.
