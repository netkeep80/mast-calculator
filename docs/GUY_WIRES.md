# Дополнительные растяжки мачты — issue #23

## Назначение

Страница `site/guys.html` добавляет отдельный инженерный режим расчёта модульной мачты с дополнительными стальными растяжками.

Пользователь задаёт:

- число ярусов;
- высоту крепления каждого яруса;
- 3–6 растяжек на ярус;
- расстояние от оси мачты до анкеров;
- поворот схемы анкеров по азимуту;
- тип и диаметр троса;
- преднатяг каждой растяжки;
- коэффициент запаса троса;
- эффективность фактической заделки.

Для каждой растяжки выводятся:

- фактический узел и фактическая высота крепления;
- длина;
- угол к земле и к вертикали;
- минимальное и максимальное натяжение по ветровой огибающей;
- расчётная рабочая нагрузка;
- использование `U`;
- факт полного разгружения/провисания;
- в определяющем случае — вектор реакции узла модуля и нагрузка на анкер.

## Почему крепление привязывается к узлу

Основная FEM-модель мачты имеет по три узла на каждом интерфейсе модулей. Сосредоточенную силу растяжки физически корректно прикладывать к конструктивному узлу, а не к середине арматурного ребра без дополнительной детали и отдельной локальной модели.

Поэтому введённая высота округляется до ближайшего уровня модуля:

```text
level = round(Hrequested / hmodule)
Hactual = level * hmodule
```

Программа показывает как запрошенную, так и фактическую высоту через `heightSnapM`.

На выбранном уровне 3–6 растяжек распределяются между тремя физическими узлами максимально равномерно. Выбирается циклический сдвиг, дающий минимальную суммарную угловую разницу между узлами и анкерами. Поэтому неоднозначность на уровнях, повёрнутых на 60°, не может случайно превратить симметричные три растяжки в схему `2+1+0`.

## Геометрия одной растяжки

Для узла крепления `x` и неподвижного анкера `a`:

```text
r = a - x
L = |r|
q = r/L
```

`q` направлен от узла мачты к анкеру.

Угол к горизонту:

```text
alpha = atan2(|dz|, sqrt(dx^2 + dy^2))
```

Расстояние до анкера в UI — горизонтальный радиус от оси мачты, а не длина троса.

## Каталог тросов

### Оцинкованный 6×19 со стальным сердечником

Использованы коэффициенты класса 6×19 из EN 12385-4 для стального сердечника:

```text
Ametal = C2*d^2,    C2 = 0.449
m100   = W2*d^2,    W2 = 0.400 kg/100m
Fmin   = K2*d^2*Rr, K2 = 0.356
Rr     = 1770 MPa
```

Встроенные диаметры: 4, 5, 6, 8, 10, 12, 14, 16 мм.

Эффективный модуль каната по умолчанию принят `Eeff = 82 GPa`. Это именно параметр деформативности свитого каната, а не модуль стали проволоки. Он является инженерным значением модели и должен заменяться паспортным значением конкретного изделия, если оно известно.

### Нержавеющий AISI 316 7×19

Для диаметров 3, 4, 5, 6, 7, 8, 10, 12 мм встроены табличные значения массы и минимальной разрывной нагрузки для каната 7×19 класса 1570 MPa.

`Eeff = 80 GPa` используется как предварительное значение модели. Эквивалентная металлическая площадь восстановлена из разрывной нагрузки только для расчёта осевой жёсткости и не должна трактоваться как геометрическая площадь конкретной конструкции каната.

## Расчётная рабочая нагрузка

Встроенный справочник хранит минимальную разрывную нагрузку `Fmin`, но проходной критерий использует более низкую расчётную рабочую нагрузку:

```text
Fterminated = Fmin * eta_terminal
Fworking    = Fterminated / gamma_guy
```

По умолчанию:

```text
eta_terminal = 0.80
gamma_guy    = 3.0
```

Эти коэффициенты видимы и настраиваются пользователем. Они не заменяют проверку конкретного талрепа, коуша, зажимов, опрессовки и анкера.

## Constitutive law: только растяжение

Растяжка не воспринимает сжатие.

Начальный преднатяг `T0` задаёт эквивалентную предварительную деформацию. Для текущей длины `L`:

```text
kax = Eeff*Ametal/L0
Traw = T0 + kax*(L - L0)
T = max(0, Traw)
```

Если `Traw <= 0`, растяжка становится slack и полностью исключается из касательной жёсткости до тех пор, пока геометрия снова не даст положительное натяжение.

## Касательная жёсткость кабеля

Для натянутого прямого кабеля используется 3×3 касательная матрица в узле крепления:

```text
Kt = kax*(q*q^T) + (T/L)*(I - q*q^T)
```

Первое слагаемое — осевая материальная жёсткость.

Второе — геометрическая поперечная жёсткость от уже существующего натяжения. Именно поэтому преднатянутый трос стабилизирует поперечное перемещение мачты даже до заметного осевого удлинения.

## Newton-итерация

Сила кабеля на узел:

```text
f(u) = T(u) * q(u)
```

Её производная по перемещению узла равна `-Kt`. В точке `u0`:

```text
f(u) ~= f(u0) - Kt*(u-u0)
```

Поэтому на очередной итерации решается абсолютная система:

```text
(Kmast + Kt) * u = Fexternal + f(u0) + Kt*u0
```

После решения пересчитываются:

- текущая длина;
- направление;
- натяжение;
- slack/active состояние;
- касательная жёсткость.

Итерации продолжаются до одновременного выполнения допусков по изменению перемещений и натяжений.

По умолчанию:

```text
max iterations = 25
absolute displacement change <= 1e-8 m
relative tension change <= 1e-6
```

Если итерация не сошлась, весь расчёт помечается непроходным.

## Реакции

В определяющем ветровом случае для каждой растяжки доступны:

```text
forceOnMastN
moduleNodeReactionN = -forceOnMastN
anchorLoadN         = -forceOnMastN
```

`moduleNodeReactionN` — вектор, который конструктивный узел модуля должен передать в растяжку.

`anchorLoadN` — вектор силы, которой трос тянет анкер. По его модулю надо отдельно проверять грунтовый анкер и его детали.

Кабель считается шарнирно закреплённым и локальный момент в узел не передаёт.

## Ветровая огибающая

Для голой трёхгранной мачты основной solver может использовать эквивалентность направлений через 120°. Для мачты с произвольными 3–6 растяжками такое сокращение в общем случае неверно: например, четыре или пять анкеров нарушают 120-градусную симметрию.

Поэтому `guyWindDirections()` при включённой огибающей всегда перебирает полный круг `0 <= angle < 360` с заданным пользователем шагом. При шаге 30° это 12 отдельных нелинейных расчётных случаев.

## Критерии прохождения

Общий результат `passes=true` только если одновременно:

```text
Umember <= 1
Uwire   <= 1
delta_top <= delta_limit
lambda_cr >= lambda_required
Newton converged for every wind case
```

## Сравнение с мачтой без растяжек

UI дополнительно выполняет штатный `calculateMast()` для тех же исходных параметров и показывает прогиб без растяжек рядом с результатом новой модели. Это позволяет сразу увидеть реальный выигрыш от ярусов и выбранного преднатяга.

## Что сознательно не моделируется

Текущая реализация не учитывает:

- catenary/провисание и распределённое действие собственного веса троса;
- распределённую ветровую нагрузку на сам трос;
- лёд на самом тросе;
- динамику порывов и вибрации растяжек;
- аэродинамическое возбуждение и galloping;
- пластичность проволок;
- усталость;
- податливость анкеров и грунта;
- податливость талрепов и заделок;
- местную прочность детали, которой трос присоединён к узлу октаэдра.

Масса троса в интерфейсе показывается как ведомость материала, но пока не превращается в распределённую FEM-нагрузку. Это согласуется с принятой прямолинейной cable-моделью; для длинных и тяжёлых растяжек следующим шагом должна быть catenary-модель с собственным весом.

Это линейно-упругая FEM мачты плюс геометрически нелинейная модель прямых tension-only кабелей. Для окончательного рабочего проекта нужны отдельные проверки анкеров, узлов, усталости и фактических сертификатов троса.
