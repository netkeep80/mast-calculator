# Конфигуратор соединительного узла

Статус: прототип **1.2**, issue #21.

## 1. Зачем упрощён конфигуратор

Пользователь не должен вводить внутренние расчётные параметры узла, если они однозначно следуют из выбранных стандартных деталей. Основной интерфейс теперь оперирует тем, что реально покупается и сваривается:

```text
болт
обычная проходная гайка на ножке
длинная соединительная гайка верхнего узла
длина ввинчивания болта
сварочный материал
катет и число участков шва
```

По возможности используются выпадающие списки. В режиме **«Автоподбор узла»** программа сама выбирает согласованный комплект.

## 2. Реальная физическая схема

Один межмодульный стык состоит из двух разных гаек и одного вертикального болта.

### Верхний узел нижнего модуля

Используется **длинная соединительная гайка** с той же метрической резьбой, что и болт.

```text
4 ребра арматуры
       \ | /
    [ длинная ]
    [ гайка Mx ]  <- болт ввинчивается сюда
```

К наружным граням этой гайки приварены четыре ребра модуля. Увеличенная длина гайки даёт большую доступную длину резьбового зацепления.

В текущем каталоге для M16…M36 используется справочная геометрия DIN 6334 с длиной `3d`. Для M42/M48 та же `3d`-геометрия используется как расчётная компоновка и должна быть подтверждена по каталогу конкретного поставщика.

### Конец ножки верхнего модуля

К обычной шестигранной гайке приварены **два ребра** ножки. Номинальная резьба этой гайки больше диаметра соединительного болта.

```text
2 ребра
 \   /
 [ гайка My ]   y > x
      |
      | болт Mx проходит свободно
      v
 [ длинная гайка Mx ]
```

Болт **не ввинчивается** в гайку ножки. Он проходит через её внутреннюю резьбу как через отверстие и работает резьбой только в длинной соединительной гайке нижнего модуля.

## 3. Проверка свободного прохода

Для предварительной геометрической проверки используется базовый внутренний диаметр метрической резьбы:

```text
D1 = D - 1.082532·P
```

где:

- `D` — номинальный диаметр резьбы проходной гайки;
- `P` — шаг;
- `D1` — базовый внутренний диаметр.

Условие текущего конфигуратора:

```text
D1 - d_bolt >= 0.5 мм
```

Это геометрический фильтр для подбора. Он **не заменяет** проверку реального приобретённого изделия калибром/болтом: фактический внутренний профиль зависит от поля допуска резьбы, покрытия и производителя.

Пример для M24:

```text
болт M24
проходная гайка M30×3.5
D1 ≈ 30 - 1.082532·3.5 = 26.21 мм
диаметральный запас ≈ 2.21 мм
```

Поэтому M24 свободно проходит через выбранную M30 в принятой расчётной геометрии.

## 4. Длинная соединительная гайка

Для выбранного болта `Mx` соединительная гайка автоматически получает ту же резьбу `Mx`.

Справочная длина:

```text
Lcoupling = 3d
```

Для M24:

```text
Lcoupling = 3·24 = 72 мм
```

Размер под ключ используется для автоматического получения эффективного радиуса текущей упрощённой модели передачи момента:

```text
reff = s/2
```

Таким образом пользователь больше не вводит `reff` произвольно.

## 5. Длина зацепления резьбы

По умолчанию конфигуратор задаёт:

```text
Lengagement = 2d
```

В ручном режиме доступны варианты `1d`, `1.5d`, `2d`.

Число зацепленных витков:

```text
n = Lengagement/P
```

Для M24×3 при `2d`:

```text
Lengagement = 48 мм
n = 48/3 = 16 витков
```

Важно: это **правило компоновки**, а не законченная проверка срыва резьбы. Пока материал конкретной соединительной гайки и точный профиль/поле допуска не формализованы, приложение не имеет права выдавать `2d` как доказанную несущую способность внутренней резьбы.

## 6. Автоматический подбор длины болта

Минимальная длина считается от верхней опорной поверхности проходной гайки до конца требуемого зацепления в длинной гайке:

```text
Lrequired = m_clearance_nut + Lengagement + aassembly
```

где текущий монтажный запас:

```text
aassembly = 2 мм
```

После этого выбирается ближайшая большая длина из стандартного выпадающего ряда.

Для практической сборки M24/M30:

```text
m(M30) = 25.6 мм
Lengagement = 48 мм
aassembly = 2 мм
Lrequired = 75.6 мм
=> выбран болт 80 мм
```

То есть известная практическая конфигурация `M24×80 + проходная M30 + длинная M24×72` получается из правил автоматически.

## 7. Автоподбор узла

В режиме `auto` алгоритм работает от расчётного требования к физической детали.

Для каждого расчётного межмодульного узла сначала сохраняются совпадающие в одном load case:

```text
F = [Fx,Fy,Fz]
M = [Mx,My,Mz]
```

Для каждого кандидата болта заново строится его собственная геометрия и `reff`, после чего demand переводится в:

```text
Nt = max(0,-Faxis) + |Mb|/reff
Ns = |Fperp| + |T|/reff
```

Проверка болта:

```text
Nbs = Rbs·Ab·ns·γb·γc
Nbt = Rbt·Abn·γc
Ubolt = sqrt((Ns/Nbs)^2 + (Nt/Nbt)^2)
```

Автоподбор начинает с класса **8.8** и ищет минимальный проходящий стандартный диаметр. Если весь поддерживаемый ряд 8.8 не проходит, проверяются 10.9 и 12.9. Классы 5.6/5.8 сохраняются в полном каталоге/ручном режиме и таблице рекомендаций.

Одновременно автоматически выбираются:

```text
проходная гайка большего диаметра
длинная соединительная гайка того же диаметра, что болт
длина болта
длина зацепления
эффективный радиус
совместимый электрод
базовый катет шва
число участков шва
```

## 8. Фиксация детали после автоподбора

Это принципиально важно для корректности предельных расчётов.

После того как operational load cases выбрали физическую сборку, она **фиксируется**. Боковая грузоподъёмность, максимальная статическая масса и поиск высоты не имеют права незаметно увеличивать болт при росте пробной нагрузки.

Поэтому полный пользовательский расчёт выполняет:

```text
1. эксплуатационная FEM-огибающая
2. автоподбор физического узла
3. фиксация выбранных деталей
4. боковая предельная проверка с этим же узлом
5. статическая предельная проверка с этим же узлом
6. поиск максимальной высоты с этим же узлом
```

## 9. Ручной режим

Ручной режим нужен для проверки уже имеющихся деталей.

Пользователь выбирает из списков:

```text
диаметр болта
класс болта
проходную гайку
длину болта
1d / 1.5d / 2d зацепления
электрод/проволоку
катет шва
число участков шва
```

Соединительная гайка не выбирается независимо: её резьба обязана совпадать с болтом. Её длина и `reff` показываются как производные readonly-параметры.

Если болт слишком короток, выбранная проходная гайка не даёт требуемого свободного прохода или заданное зацепление не помещается в соединительную гайку, геометрия получает `FAIL` независимо от прочности болта.

## 10. 3D-визуализация

Отдельное окно `Соединительный узел: две гайки и болт` показывает:

- длинную соединительную гайку;
- проходную гайку ножки;
- болт;
- участок резьбового зацепления;
- четыре условных ребра на соединительной гайке;
- два условных ребра на проходной гайке.

Окно можно вращать и масштабировать. Это схема компоновки, а не CAD-модель резьбы или сварных валиков.

## 11. Сварка

Глобальная FEM по-прежнему считает идеальный жёсткий арматурный каркас. После неё каждый конец ребра проверяется отдельным weld-layer.

В `auto`:

- выбирается первый совместимый покрытый электрод;
- катет берётся из стандартного списка по практическому правилу не меньше примерно `dbar/3`;
- базово используются 3 непрерывных участка на конец.

Затем фактический weld demand проверяется существующими формулами проекта. Если автоматически выбранной геометрии шва недостаточно, результат не должен скрываться.

## 12. Что ещё не доказано текущей моделью

Issue #21 упрощает и делает физически однозначной **конфигурацию** узла, но не отменяет прежние инженерные границы:

- срыв внутренней/наружной резьбы пока не рассчитан по материалу конкретной гайки;
- фактическое поле допуска и покрытие резьбы не моделируются;
- смятие, prying, preload и slip не моделируются;
- точные координаты сварных валиков пока заменены принятой weld-group surrogate;
- податливость реального соединения не возвращается в глобальную матрицу `K`;
- геометрия купленной гайки должна быть сверена с паспортом/каталогом поставщика.

Поэтому автоконфигуратор выбирает **согласованную расчётную компоновку**, а не выдаёт сертификат конкретной покупной метизы.

## 13. Автоматические проверки

Отдельный CI gate `Joint configurator` проверяет как минимум:

```text
M24 -> минимальная проходная M30
M24 -> длинная M24×72
2d -> 48 мм -> 16 витков
M24/M30 -> минимально 75.6 мм -> стандартный болт 80 мм
короткий M24×70 -> FAIL геометрии
auto 100 кН -> минимальный M20 8.8 с согласованными гайками/длиной
manual -> выбранные M24/M30/80 не заменяются
полный расчёт -> один выбранный узел фиксирован для всех предельных проверок
```

Эти тесты также входят в общий `npm test` и выполняются на Linux, macOS и Windows.
