# Справочники и масса физической сборки

Статус: прототип 1.3, issue #27.

## 1. Цель

Пользователь должен иметь возможность ответить на два разных вопроса:

1. **Какие именно исходные численные данные использует программа?**
2. **Сколько примерно весит реальная изготовленная деталь, а не только арматурный FEM-каркас?**

Для этого в интерфейсе появились single-source справочники и отдельная производственная оценка массы.

## 2. Принцип единого источника истины

Reference UI не содержит вручную переписанных `Ry`, `Rm`, `Rbt`, `Abn` и других чисел.

```text
calculation catalog
       │
       ├── solver / connection checks
       │
       └── buildReferenceData()
                 │
                 └── browser reference tables
```

Если расчётный каталог меняется, справочник меняется вместе с ним. CI отдельно сравнивает размеры наборов и ключевые значения.

Схема reference data:

```text
mast-calculator/reference-data/v1
```

## 3. Арматура

Источник расчётных свойств класса хранится в `site/engine/catalog.js`.

Для каждого класса показываются:

```text
Ry
Rm
E
ν
ρ
признак гарантированной свариваемости
нормативный источник
```

Для каждого поддерживаемого диаметра дополнительно вычисляются:

```text
A = πd²/4
m1m = ρA
```

Масса 1 м в таблице не является ещё одной каталожной константой: она каждый раз вычисляется из диаметра и плотности стали.

## 4. Болты

Прочностной расчёт использует:

```text
Rbun
Rbs
Rbt
Ab
Abn
```

из существующего connection catalog.

Для справочника и оценки массы к размеру болта добавлена справочная геометрия шестигранной головки:

```text
s — размер под ключ
k — высота головки
```

Она не участвует в расчёте несущей способности болта.

### Оценка массы болта

Для прозрачной производственной оценки используется:

```text
Vshaft = πd²/4 · L
Vhead  = √3/2 · s² · k
mbolt  = ρ · (Vshaft + Vhead)
```

Это намеренно простая геометрическая модель. Она не вычитает резьбовой профиль, фаски и скругления, поэтому её нельзя выдавать за паспортную массу конкретного изделия.

## 5. Гайки

Обычные проходные гайки и длинные соединительные гайки выводятся из того же `joint-hardware-catalog.js`, который использует конфигуратор.

### Оценка массы гайки

Наружная форма принимается шестигранной призмой, отверстие — цилиндром по базовому внутреннему диаметру метрической резьбы:

```text
Ahex = √3/2 · s²
D1 = D − 1.082532P
Vnut = (Ahex − πD1²/4) · h
mnut = ρ · Vnut
```

Для длинной гайки вместо `h` используется её длина.

Фаски и винтовой профиль резьбы не моделируются.

## 6. Сварка

Расчёт длины сварки по-прежнему выполняется `weld-check.js` по совпадающему `N/V/T/M` одного load case.

Для оценки массы наплавленного металла поперечное сечение углового шва принимается идеальным прямоугольным равнобедренным треугольником:

```text
Aweld ≈ k²/2
Vweld = Aweld · Lphysical
mweld = ρ · Vweld
```

Это оценка массы наплавленного металла, а не модель реального усиления валика.

## 7. Масса одного ребра

```text
mrib = ρ · πd²/4 · a
```

где `a` — фактическая расчётная длина ребра, полученная из закупочного раскроя.

В интерфейсе масса ребра видна ещё до запуска полного расчёта.

## 8. Масса полного межмодульного узла

В issue #27 под «узлом с учётом сварки» фиксируется одна законченная физическая сборка:

```text
1 длинная соединительная гайка
1 проходная гайка ножки
1 болт
6 сваренных концов рёбер
```

Поэтому:

```text
Mjoint = Mbolt + MclearanceNut + McouplingNut + 6·MweldEnd
```

Это именно масса соединительного комплекта, а не масса шести примыкающих рёбер.

## 9. Масса сваренного и закреплённого модуля

Один физический модуль содержит:

```text
9 рёбер
3 длинные соединительные гайки
3 проходные гайки
3 болта
18 сваренных концов рёбер
```

Следовательно:

```text
Mmodule = 9·Mrib
        + 3·(Mbolt + MclearanceNut + McouplingNut)
        + 18·MweldEnd
```

### Почему для 18 концов берётся одинаковая длина шва

Расчётная огибающая может потребовать разные длины на разных концах. Но физический модуль задуман как повторяемое изделие. Поэтому для производственной оценки используется консервативное правило:

```text
Lweld,module = max(requiredPhysicalLength всех концов и cases)
```

и эта длина применяется ко всем 18 концам.

В snapshot/result дополнительно сохраняется сумма индивидуальных длин огибающей, чтобы позже можно было сравнить унифицированный и оптимизированный поштучный вариант.

## 10. Почему сборочная масса пока не включена в FEM self-weight

Текущий FEM собственный вес собирается до решения и зависит только от геометрии арматурных members.

Но требуемая длина шва становится известна после решения:

```text
FEM loads
  ↓
N/V/T/M
  ↓
required weld length
  ↓
weld mass
```

Если немедленно добавить эту массу обратно в ту же линейную процедуру, возникает цикл:

```text
нагрузка → усилия → шов → масса → нагрузка → ...
```

Прототип 1.3 не скрывает этот вопрос и не делает неявную одношаговую аппроксимацию. Поэтому:

```text
FEM self-weight = масса арматурных рёбер
fabrication mass = отдельная производственная оценка
```

Для включения массы метизов и сварки в расчётную нагрузку следует отдельно определить согласованную схему: фиксированная заранее конструктивная длина шва либо итерационный расчёт до сходимости.

## 11. Что проверяет CI

`tests/assembly-mass.test.js` проверяет:

- `ρπd²/4` для погонной массы;
- линейность массы шва по длине;
- квадратичность по катету;
- положительную воспроизводимую массу M24×80/M30/длинной M24;
- точную композицию массы узла;
- точную композицию массы модуля;
- явный признак того, что fabrication mass пока не включена в global FEM self-weight.

`tests/reference-data.test.js` проверяет, что reference layer строится из тех же наборов, что и расчётные каталоги.
