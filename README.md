# Калькулятор мачты

Статическое браузерное приложение для расчёта модульной мачты из сварных арматурных октаэдров. Backend не требуется: вычисления выполняются в Web Worker непосредственно в браузере, публикация — через GitHub Pages.

Опубликованная версия: **https://netkeep80.github.io/mast-calculator/**

## Прототип 1.2

Версия 1.2 сохраняет расчётную модель 1.1 и меняет практический слой межмодульного соединения. Теперь пользователь работает с реальной сборкой из **двух гаек и одного болта**, а не вводит искусственный эффективный радиус вручную.

### Физический модуль

Каждый правильный октаэдр установлен **ножками вниз**:

```text
3 ребра верхнего треугольника
6 диагональных ножек
-----------------------------
9 рёбер на модуль
```

Геометрия:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = a*sqrt(2/3)
H = N*h
```

Три нижних узла первого модуля пока являются идеальной жёсткой заделкой по всем шести степеням свободы.

## Упрощённый соединительный узел

Реальный стык теперь задан однозначно.

### Гайка ножки

На конце ножки к обычной шестигранной гайке приварены **два ребра**. Её номинальная резьба выбирается больше диаметра болта, чтобы болт проходил через внутренний профиль свободно и **не ввинчивался** в эту гайку.

### Длинная соединительная гайка

В верхнем узле нижнего модуля к длинной соединительной гайке приварены **четыре ребра**. Резьба гайки совпадает с резьбой болта, и именно в неё болт ввинчивается.

Для M16…M36 в каталоге используется справочная геометрия длинной гайки `3d`. Конкретную покупную деталь всё равно надо сверять с каталогом поставщика.

### Пример M24

Правила конфигуратора автоматически дают практическую сборку:

```text
болт                    M24
проходная гайка ножки   M30
длинная гайка           M24 × 72 мм
зацепление              2d = 48 мм = 16 витков
минимально требуется    75.6 мм
стандартная длина болта 80 мм
```

То есть известная конструкция `M24×80 + M30 + длинная M24` больше не требует ручного ввода внутренних расчётных величин.

Подробности и формулы: [`docs/JOINT_CONFIGURATOR.md`](docs/JOINT_CONFIGURATOR.md).

## Два режима конфигуратора

### Автоподбор узла

Основной режим. По расчётным результирующим `F/M` программа:

1. перебирает стандартные болты;
2. начинает с практического класса 8.8;
3. для каждого кандидата подбирает проходную гайку;
4. назначает длинную гайку того же диаметра, что болт;
5. вычисляет эффективный радиус из геометрии гайки;
6. назначает длину зацепления;
7. выбирает ближайшую достаточную стандартную длину болта;
8. выбирает базовый совместимый электрод и параметры шва;
9. проверяет фактический demand.

В режиме подбора диаметра арматуры конфигуратор узла автоматически переключается в `auto`.

### Ручная конфигурация

Для проверки уже имеющихся деталей пользователь выбирает из выпадающих списков:

```text
диаметр и класс болта
проходную гайку
длину болта
1d / 1.5d / 2d зацепления
сварочный материал
катет
число участков шва
```

Длинная соединительная гайка и эффективный радиус остаются производными readonly-параметрами.

## Отдельная 3D-схема узла

В интерфейсе появилось окно **«Соединительный узел: две гайки и болт»**. Оно показывает длинную соединительную гайку, проходную гайку ножки, центральный болт, участок резьбового зацепления, четыре условных ребра верхнего узла и два условных ребра ножки.

Схему можно вращать и масштабировать. Это визуализация компоновки, а не CAD-модель профиля резьбы или сварных валиков.

## Один узел для всех предельных расчётов

Автоподбор не может «подыгрывать» задаче, увеличивая болт при каждом пробном усилии. Поэтому полный пользовательский расчёт выполняется так:

```text
эксплуатационная FEM-огибающая
        ↓
автоподбор физического узла
        ↓
фиксация выбранной сборки
        ↓
боковая несущая способность
максимальная статическая масса
поиск максимальной высоты
```

Все три специальные предельные проверки используют **один и тот же уже выбранный физический узел**.

## Три независимых вычислительных пути

Статическая рамная задача проверяется тремя путями:

1. global FEM — symmetric-band Cholesky;
2. module-by-module — точная Schur-конденсация;
3. independent dense reference FEM — отдельная сборка + Gaussian elimination.

CI сравнивает все перемещения/повороты, реакции и 12 локальных концевых усилий каждого элемента. Для выбранных случаев также независимо сравнивается `λcr`.

Production general buckling решает полную задачу:

```text
(K + lambda*KG)*phi = 0
```

и не заменяется последовательной проверкой отдельных модулей.

## Основные расчётные возможности

Сохраняются собственный вес, обледенение, пространственный ветер, оборудование, ветровая огибающая, прочность рёбер по совместному `N/V/T/M`, локальная проверка по Эйлеру, общая потеря устойчивости, боковая предельная сила, максимальная статическая масса, поиск максимальной высоты, межмодульный болт, сварные концы, подробная визуализация модулей, ведомость рёбер, CSV, бумажный расчётный проект и паспорт верификации.

## Логотип

Пользовательский `logo.jpg` хранится в корне репозитория. CI smoke-test и Pages packaging проверяют его наличие; при публикации файл копируется в корень Pages-артефакта и используется в шапке приложения.

## Что пока не доказано

Совпадение трёх внутренних решателей и автоматическая конфигурация метизов не превращают прототип в нормативный сертификат. Пока остаются открытыми:

- P-Delta / геометрическая нелинейность;
- начальные несовершенства;
- пластичность;
- конечная податливость реального соединения;
- срыв внутренней/наружной резьбы по материалу конкретной гайки;
- фактические поля допуска/покрытия резьбы;
- смятие, prying, предварительная затяжка и проскальзывание;
- точные координаты сварных валиков;
- усталость;
- параметрический фундамент;
- полный набор нормативных сочетаний;
- независимая проверка реальной мачты сторонним КЭ-комплексом.

## CI/CD

Обязательные PR checks:

```text
Syntax, policy and maintainability
Secrets scan
Triple FEM equivalence
Joint configurator
Tests: Ubuntu / macOS / Windows
Static site smoke
```

`Joint configurator` отдельно проверяет физическую топологию двух гаек, свободный проход, автоматическую длину болта, ручной режим и фиксацию выбранной сборки в предельных расчётах.

## Локальный запуск

Так как исходный `logo.jpg` лежит в корне репозитория:

```bash
python3 -m http.server 8080
```

Открыть:

```text
http://localhost:8080/site/
```

Для тестов:

```bash
npm test
npm run test:triple
npm run test:joint
npm run check
node scripts/check-file-line-limits.mjs
```

Runtime npm dependencies отсутствуют.
