# Аналитическая проверка реакций трёх опор

Статус: verification oracle для issue #26.

## 1. Зачем нужен отдельный тест

Сложная FEM может иметь малую численную невязку и при этом содержать ошибку в геометрии, сборке нагрузок или восстановлении реакций. Поэтому полезны задачи, где ответ следует напрямую из статики твёрдого тела и не зависит от жёсткости отдельных рёбер.

Issue #26 задаёт три таких случая для нижнего треугольника мачты:

```text
чистый вес            -> 1/3, 1/3, 1/3
результирующая на ребре -> 0,   1/2, 1/2
результирующая в вершине -> 1,   0,   0
```

В тестах используются настоящая геометрия нескольких модулей, настоящие distributed self-weight loads и два независимых FEM-решателя. Ожидаемые реакции при этом вычисляются не FEM, а аналитически.

## 2. Важная граница постановки

Точные отношения выше справедливы для трёх **точечных опор без опорных моментов**. Такая опора запрещает перемещения:

```text
ux = uy = uz = 0
```

но не запрещает вращения:

```text
rx, ry, rz — свободны
```

Production-модель Mast Calculator пока использует более жёсткую идеализацию фундамента — полную заделку всех шести DOF. В ней опорные моменты могут нести часть опрокидывающего момента, поэтому значения `0 / W/2 / W/2` и `W / 0 / 0` не обязаны выполняться для `analysis.reactions` отдельно от `analysis.reactionMoments`.

Поэтому `tests/support-reactions.test.js` создаёт **verification fixture**: берёт production-геометрию мачты без изменений и отпускает только три вращения каждого из трёх нижних узлов. Это не меняет расчётную модель приложения и не выдаёт шарнирный фундамент за фактический.

## 3. Независимый вес и центр тяжести

Для каждого ребра тест независимо вычисляет:

```text
A = pi*d^2/4
Li = |Bi - Ai|
Wi = rho*A*Li*g*gamma_g
```

Полный собственный вес:

```text
W = sum(Wi)
```

Центр тяжести стержневой системы:

```text
CG = sum(Wi*Mi) / W
Mi = (Ai + Bi)/2
```

После этого отдельно проверяется, что `buildLoadCase().selfWeightN` совпадает с независимым `W`.

Для симметричной мачты горизонтальные координаты `CG` должны быть практически нулевыми.

## 4. Рычаг горизонтальной силы

Горизонтальная сила `F` прикладывается равномерно к трём верхним узлам. Её результирующая проходит через центр верхней грани на высоте `H` над плоскостью опор.

Опрокидывающий момент:

```text
M = F*H
```

Чтобы центр вертикальных опорных реакций сместился от горизонтальной проекции `CG` на расстояние `e`, требуется:

```text
W*e = F*H
F = W*e/H
```

Именно `H` — высота точки приложения горизонтальной силы над опорной плоскостью — является нужным рычагом. Высота центра тяжести в эту формулу не входит, потому что собственный вес вертикален.

## 5. Равносторонний опорный треугольник

Для стороны `a`:

```text
R = a/sqrt(3)        — расстояние от центра до вершины
r = a/(2*sqrt(3))    — расстояние от центра до противоположной стороны
r = R/2
```

Отсюда две контрольные силы:

```text
Fedge   = W*r/H = W*a/(2*sqrt(3)*H)
Fvertex = W*R/H = W*a/(sqrt(3)*H)
Fvertex = 2*Fedge
```

Тест не хранит эти силы как магические числа: `W`, `a`, `H`, направление и эксцентриситет вычисляются из фактической FEM-геометрии.

## 6. Контроль №1: нулевой ветер

При отсутствии горизонтальных внешних нагрузок результирующая веса проходит через центр опорного треугольника.

Из симметрии и равновесия:

```text
R0 + R1 + R2 = W
R0 = R1 = R2
```

следовательно:

```text
R0 = R1 = R2 = W/3
```

Это одновременно проверяет собственный вес, симметрию геометрии, consistent distributed loads и восстановление опорных реакций.

## 7. Контроль №2: результирующая на противоположном ребре

Берётся вершина `0`, а целевая точка — середина линии между опорами `1` и `2`.

Сила направлена от центра к этой линии и имеет величину:

```text
Fedge = W*r/H
```

В предельном статическом положении центр вертикальных реакций лежит на середине ребра `1–2`. Поэтому:

```text
R0 = 0
R1 = W/2
R2 = W/2
```

Тест дополнительно восстанавливает barycenter из рассчитанных `Ri` и проверяет, что он совпадает с геометрической серединой ребра.

## 8. Контроль №3: результирующая в вершине

Сила направлена от центра к опоре `0`:

```text
Fvertex = W*R/H
```

Тогда:

```text
R0 = W
R1 = 0
R2 = 0
```

И снова barycenter рассчитанных вертикальных реакций обязан совпасть с координатой опоры `0`.

## 9. Два независимых численных пути

Каждый из трёх аналитических случаев считается двумя FEM-решателями:

```text
production: symmetric-band Cholesky
reference:  independent dense Gaussian FEM
```

Сравниваются:

- три вертикальные опорные реакции с аналитическим ответом;
- сумма реакций с `W`;
- barycenter вертикальных реакций с целевой точкой;
- реакции двух решателей между собой;
- residual каждого решателя.

Reference solver не импортирует production `solver.js`, `banded.js` или `module-stack.js`, поэтому совпадение не является простым повторным запуском одного алгоритма.

## 10. CI gate

Для этих проверок существует отдельная команда:

```bash
npm run test:statics
```

и отдельный PR job:

```text
Support reaction statics
```

Полный `npm test` также включает эти тесты.

## 11. Что именно доказывают эти тесты

Они дают сильное независимое свидетельство, что при статически определимых опорах корректно работают:

- координаты опор и верхней грани;
- масса и распределённый собственный вес;
- преобразование distributed loads в consistent nodal loads;
- глобальная сборка матрицы и load vector;
- решение frame FEM;
- восстановление сил элементов;
- восстановление опорных реакций;
- глобальное равновесие сил и моментов.

Они **не доказывают**, что реальный фундамент является шарнирным или жёстким, и не выбирают за инженера реальную жёсткость свай/швеллеров/болтов. Это отдельная физическая задача фундамента.
