# Экспорт подробной 3D-модели мачты

Issue #28 добавляет экспорт рассчитанной мачты в **Wavefront OBJ**. Формат выбран потому, что он текстовый, не требует runtime-зависимостей и импортируется Blender, FreeCAD, MeshLab и большинством CAD/mesh-пакетов.

После issue #45 OBJ и встроенный интерактивный просмотрщик используют **один и тот же генератор polygon mesh** — `site/engine/detailed-mast-model.js`. Это исключает расхождение между тем, что пользователь видит в браузере, и тем, что затем скачивает как OBJ.

## Как скачать модель

1. Задайте конструкцию и условия эксплуатации.
2. Выполните расчёт или автоподбор.
3. В блоке экспорта нажмите **«3D модель OBJ»**.
4. Браузер скачает файл `mast-model-…obj`.

Кнопка заблокирована до получения полного расчётного `result`, потому что экспорт использует ту же геометрию и тот же физический соединительный узел, которые фактически прошли расчёт.

## Что находится в OBJ

Координаты записываются в **миллиметрах**, ось `Z` направлена вверх по мачте. Сам Wavefront OBJ не хранит декларацию единиц как отдельное машинно-читаемое поле, поэтому при импорте следует выбрать миллиметры или масштаб `1 OBJ unit = 1 mm`.

### Арматура

Каждое расчётное ребро превращается из FEM-centerline в замкнутый многогранный цилиндр:

- начало и конец берутся непосредственно из `model.nodes`;
- диаметр берётся из **самого `member.diameterM`**, а не из одного глобального UI-поля;
- поэтому после поддержки смешанных диаметров модулей OBJ корректно сохраняет фактический Ø каждого модуля;
- по умолчанию окружность аппроксимируется 12 гранями;
- каждый member получает отдельный OBJ-object с номером модуля и ролью (`top-ring` / `leg`).

Таким образом, выгружается не проволочный граф и не скриншот текущего canvas, а полноценная polygon mesh геометрия всей мачты.

### Соединительный узел

Если расчёт содержит `connections.configurator.geometry`, общая подробная модель повторяет фактически выбранную сборку по всем физическим уровням:

- длинные соединительные гайки верхних узлов модулей;
- проходные гайки нижних узлов модулей;
- полые отверстия гаек по расчётному/справочному внутреннему диаметру;
- стержень болта;
- шестигранную головку болта.

На внутреннем уровне мачты присутствуют обе гайки и соединяющий их болт. На нижнем уровне есть проходная гайка нижнего модуля, на верхнем — длинная гайка верхнего модуля.

Размеры берутся из того же `joint-hardware-catalog.js`, который использует конфигуратор и расчёт соединения. Отдельного «красивого» каталога для экспорта или viewer нет.

После issue #19 каталог крепежа расширен промежуточными метрическими размерами. Подробная модель автоматически использует именно ту гайку и тот болт, которые выбрал актуальный конфигуратор; собственного устаревающего списка размеров у экспортера нет.

## Общий mesh API после issue #45

Геометрия строится функцией:

```js
import { buildDetailedMastModel } from './engine/detailed-mast-model.js'

const mesh = buildDetailedMastModel(calculationResult)
```

Схема результата:

```text
mast-calculator/detailed-mast-model/v1
  units: mm
  objects[]
    name
    group
    kind
    memberId / moduleIndex / moduleIndices
    vertices[][]
    faces[][]
  bounds
  statistics
```

`createMastObj()` теперь является сериализатором этой структуры в Wavefront OBJ, а `MastViewer` рисует ту же структуру в основном Canvas. Геометрические примитивы больше не реализованы отдельно в двух местах.

## Намеренные ограничения

OBJ является **подробной инженерной mesh-моделью**, но не выдаётся за производственную CAD-модель резьбового соединения.

Не моделируются:

- винтовой профиль резьбы;
- реальный профиль сварного валика;
- фаски, радиусы и технологические допуски конкретного производителя;
- точное подрезание концов арматуры по поверхности гайки;
- точная polygon-mesh деформация по FEM eigenmode.

Рёбра строятся по расчётным centerline-узлам, а hardware solids устанавливаются вокруг этих же узлов. Поэтому локально тела могут пересекаться. Это осознанно: текущая расчётная модель знает размеры прутка, гайки и болта, но не содержит достаточных данных для достоверного автоматического изготовления фасонных подрезок и сварных валиков. Экспорт не должен придумывать эти данные.

Дополнительные растяжки из issue #23 рассчитываются отдельным режимом `site/guys.html` и не входят в основной `calculationResult`, из которого вызывается кнопка OBJ. Поэтому текущий экспорт описывает собственно мачту и её межмодульный крепёж, а не анкеры и тросовую систему.

Закупочная смета из issue #24 также не меняет геометрию OBJ: она использует расчётные данные как источник количества и стоимости материалов, а подробная модель продолжает строиться из `model` и фактически выбранной геометрии соединительного узла.

Для изготовления соединения следует использовать расчётный проект, размеры реально приобретённых деталей и отдельную технологическую документацию.

## Программный API

OBJ-сериализатор находится в:

```text
site/engine/obj-export.js
```

Основной вызов:

```js
import { createMastObj } from './engine/obj-export.js'

const objText = createMastObj(calculationResult)
```

Дополнительные параметры передаются в общий mesh builder:

```js
createMastObj(calculationResult, {
  radialSegments: 12,
  includeJointHardware: true,
  jointGapMm: 2,
})
```

`radialSegments` ограничивается диапазоном 6…48. Для полых шестигранных гаек внутренний/внешний контур автоматически использует число сегментов, кратное шести и не меньше 12.

Интерактивный viewer сознательно использует меньшую адаптивную детализацию, чтобы вращение большой мачты оставалось отзывчивым; экспортируемая OBJ по умолчанию остаётся 12-сегментной.

## Проверки

Focused regression-suite OBJ:

```bash
npm run test:obj
```

Он проверяет:

- число mesh-объектов рёбер;
- фактические разные Ø в OBJ для смешанного профиля модулей;
- повторение long/clearance nuts и болтов по уровням двухмодульной мачты;
- отсутствие `NaN`/`Infinity`;
- корректность всех OBJ face indices;
- режим без hardware;
- наличие browser-кнопки и связи с `createMastObj`.

Общий mesh и встроенный просмотрщик дополнительно проверяются:

```bash
npm run test:viewer
```

Полный `npm test` автоматически включает оба набора тестов.
