# Mast Calculator

Статическое веб-приложение для параметрического расчёта модульной телекоммуникационной мачты. Сервер не требуется: расчёт выполняется непосредственно в браузере и приложение публикуется через GitHub Pages.

Опубликованная версия:

**https://netkeep80.github.io/mast-calculator/**

Подробная рабочая спецификация проекта: [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md).

## Прототип 0.4

В этой версии интерфейс начинает переход от «параметров КЭ-модели» к реальным параметрам изготовления:

- закупочная длина арматуры выбирается из 11,8 м и 12 м;
- выбирается, на сколько равных частей режется один пруток;
- теоретическая длина одной заготовки вычисляется автоматически и показывается только для чтения;
- диаметр арматуры выбирается из практического ряда стандартных типоразмеров;
- класс арматуры выбирается из `А400С`, `А500С`, `А600С`;
- `E`, предел текучести, временное сопротивление и плотность берутся из единого каталога материала;
- расчётные коэффициенты убраны в раскрываемый раздел;
- JSON-отчёт расширен до полного канонического снимка расчёта;
- добавлена автономная HTML «Расчётная записка», которую можно сохранить или распечатать в PDF.

### Временное правило геометрии

Сейчас используется правило:

```text
длина заготовки = закупочная длина / число частей
сторона горизонтального треугольника = длина заготовки
```

Высота модуля задаётся отдельно по фактическому размеру.

Это переходная схема. После формализации реального узла необходимо различать длину физической заготовки, длину между расчётными осями узлов, припуски/нахлёсты на сварку и ширину реза.

## Текущее расчётное ядро

Реализовано:

- генерация пространственной схемы из одинаковых модулей;
- линейный расчёт идеальной 3D-фермы методом конечных элементов;
- собственный вес стержней и вес цилиндрического слоя льда;
- ветровая нагрузка на стержни с учётом пространственной проекции и увеличения диаметра при обледенении;
- ветровая и весовая нагрузка оборудования;
- огибающая по нескольким направлениям ветра;
- проверка растянутых стержней по текучести;
- упругая проверка сжатых стержней по Эйлеру с ограничением по текучести;
- линейный собственный расчёт общей потери устойчивости по геометрической матрице жёсткости;
- визуализация первой формы общей потери устойчивости;
- контроль невязки решения, локального равновесия каждого узла и глобального равновесия;
- подбор минимального стандартного единого диаметра по прочности, отклонению и общей устойчивости;
- ведомость всех стержней по огибающей ветровых направлений;
- группировка материала по типу, диаметру и длине детали;
- экспорт CSV, полного JSON-снимка и HTML расчётной записки;
- автоматические аналитические и регрессионные тесты.

## Целевая архитектура расчёта

Глобальный расчёт и расчёт реальных узлов разделяются.

### 1. Арматурный каркас

Глобальная модель должна считать арматурный каркас так, как будто соединения являются идеальными и неразрушаемыми. При этом требование «сварено намертво» означает передачу моментов, поэтому текущая шарнирная `truss`-модель является переходной.

Целевая модель — пространственная `frame`-модель с шестью степенями свободы на узел и передачей `N`, `V`, `T`, `M`.

### 2. Реальные узлы

После глобального расчёта для каждого физического соединения формируется огибающая усилий/моментов. Отдельный модуль проверяет:

- болт/шпильку;
- метрическую резьбу и длину зацепления;
- гайку/соединительную гайку;
- сварные швы по металлу шва и границе сплавления;
- основной металл;
- эксцентриситет;
- соответствие выбранного электрода/проволоки и технологии сварки.

Узел проходит проверку только если его несущая способность не меньше спроса из глобальной модели.

## Расчётная записка и воспроизводимость

После расчёта создаётся единый `CalculationSnapshot`. Из него строятся экран результатов, CSV, JSON и HTML-записка. Генератор документа не выполняет отдельный повторный расчёт.

JSON v2 содержит без сокращения:

- исходные и автоматически полученные параметры;
- идентификатор метода;
- Git SHA опубликованной сборки;
- координаты узлов и закрепления;
- список элементов и их свойства;
- узловые нагрузки для каждого расчётного случая;
- перемещения и реакции;
- результаты каждого стержня;
- форму и множитель общей устойчивости;
- численную диагностику;
- предупреждения текущей модели.

HTML-записка содержит человекочитаемые таблицы и полный JSON в приложении. Её назначение — передать расчёт инженеру для проверки именно тех данных, которые использовала программа.

## CI/CD

Workflow `Pull request checks` запускается для каждого открытия и обновления pull request в `main`. Он выполняет:

1. модульные и аналитические тесты `npm test`;
2. синтаксическую проверку JavaScript `npm run check`;
3. запуск локального HTTP-сервера и smoke-test статических ресурсов.

Workflow `Deploy GitHub Pages` повторно прогоняет тесты, формирует Pages-артефакт и публикует сайт. `build-info.json` в опубликованной версии содержит SHA коммита, который затем попадает в расчётную записку.

## Нормативные источники

Каталоги и расчётные проверки должны хранить ссылку на конкретный нормативный источник. В рабочей спецификации зафиксированы, в частности:

- ГОСТ 34028-2016 — арматурный прокат;
- ГОСТ ISO 898-1-2014 — болты, винты, шпильки;
- ГОСТ 24705-2004 — метрическая резьба;
- СП 16.13330.2017 — стальные конструкции и сварные соединения;
- ГОСТ 5264-80 — геометрия соединений ручной дуговой сварки;
- ГОСТ 9467-75 — типы покрытых электродов;
- СП 20.13330.2016 — нагрузки и сочетания;
- ГОСТ 27751-2014 — общие принципы надёжности.

Само упоминание норматива не означает, что текущий прототип уже реализует все его требования.

## Расчёт общей устойчивости

После линейного статического расчёта по найденным продольным усилиям собирается геометрическая матрица жёсткости `K_G`. Критический множитель нагрузки определяется из задачи

```text
(K + λ K_G) φ = 0.
```

Для численного решения используется преобразование через разложение Холецкого упругой матрицы `K`, после чего вычисляется максимальное собственное значение симметричной преобразованной матрицы. В интерфейсе можно показать соответствующую нормированную форму потери устойчивости.

## Важное ограничение

Текущая версия является проверяемым физическим прототипом, а не готовым нормативным заключением. До практического применения необходимо как минимум:

- заменить `truss`-решатель на `frame`-решатель с жёсткими идеальными узлами;
- реализовать отдельные проверки болтов, резьбы, гаек и сварных швов;
- формировать нормативные сочетания нагрузок;
- добавить геометрическую нелинейность и начальные несовершенства;
- сверить эталонные задачи с независимым КЭ-комплексом.

## Локальный запуск

```bash
python3 -m http.server 8080 --directory site
```

После этого открыть `http://localhost:8080`.

Тесты расчётного ядра:

```bash
npm test
npm run check
```

Зависимостей npm у проекта нет; Node.js используется только для автоматических тестов.

## Единицы

Внутри расчётного ядра используются единицы СИ: метры, ньютоны, паскали и килограммы. Интерфейс преобразует миллиметры, гигапаскали и мегапаскали на границе системы.
