# Интегрированный просмотрщик подробной 3D-модели

Issue #45 заменяет проволочное представление основной мачты в `site/index.html` на встроенный интерактивный просмотр **той же подробной polygon-mesh модели**, которая используется для OBJ-экспорта.

Просмотрщик остаётся полностью браузерным: WebGL, Three.js, backend и runtime npm-зависимости не требуются. Рендер выполняется существующим `Canvas 2D` с painter's algorithm и простым освещением граней.

## Что теперь видно в основном окне

После расчёта `MastViewer` строит объёмную модель:

- каждое FEM-ребро становится многогранным цилиндром фактического диаметра;
- при смешанных диаметрах по ярусам используется `member.diameterM` каждого конкретного ребра;
- показываются длинные соединительные гайки;
- показываются проходные гайки;
- на внутренних стыках показываются стержни и шестигранные головки болтов;
- физический крепёж строится из того же `connections.configurator.geometry`, который прошёл расчёт соединения.

Это не декоративная копия конструкции: геометрия берётся из общего `detailed-mast-model.js`.

## Один источник геометрии для viewer и OBJ

Общий генератор:

```text
site/engine/detailed-mast-model.js
```

возвращает структуру `mast-calculator/detailed-mast-model/v1` с объектами, вершинами, гранями и инженерными метаданными.

Её используют два независимых представления:

```text
calculationResult
      │
      ▼
buildDetailedMastModel()
      ├──► MastViewer / Canvas 2D
      └──► createMastObj() / Wavefront OBJ
```

Поэтому исправление диаметра, положения ребра или геометрии крепежа одновременно меняет встроенный просмотр и выгружаемый OBJ. Отдельной «красивой» модели для UI больше нет.

## Инженерные метаданные объектов

Каждый mesh-object хранит не только полигоны, но и связь с расчётом:

- `kind` — ребро, длинная/проходная гайка, стержень/головка болта;
- `memberId` — для структурного ребра;
- `moduleIndex` и `moduleIndices` — принадлежность физическому модулю или двум соседним модулям стыка;
- `role` — `top-ring` / `leg`;
- фактический диаметр ребра.

Благодаря этому существующий выбор модуля продолжает работать и для объёмной модели: выбранный модуль и относящийся к нему крепёж визуально выделяются.

## Цвет и расчётное использование

Для арматурных рёбер сохранён инженерный смысл старой визуализации:

- зелёная область — небольшой коэффициент использования;
- по мере приближения к `U=1` оттенок идёт к красному;
- выбранный модуль показывается насыщеннее;
- крепёж имеет отдельную нейтральную стальную заливку.

Освещённость каждой грани вычисляется из её нормали уже после поворота камеры. Это только способ чтения формы и не влияет на расчёт.

## Управление

- перетаскивание мышью/указателем — вращение;
- колесо мыши или `+` / `-` — масштаб;
- стрелки клавиатуры — пошаговое вращение;
- клик по ребру — выбор физического модуля;
- двойной клик, `0` или `Home` — вернуть исходный вид.

Canvas получает `touch-action: none`, поэтому pointer-события вращения работают и на сенсорном вводе без конфликта с прокруткой страницы во время жеста на модели.

## Форма общей потери устойчивости

Режим «Форма общей потери устойчивости» не потерян. В нём:

1. исходная подробная объёмная модель остаётся полупрозрачным контекстом;
2. поверх неё рисуется увеличенная деформированная FEM-centerline форма;
3. выбранный модуль и старый алгоритм выбора по ребру продолжают работать.

Так не создаётся ложная видимость точной деформации гаек, болтов и поперечного сечения стержней: eigenmode известен для FEM-узлов, но не является CAD-деформацией всей polygon mesh.

## Производительность

OBJ по умолчанию сохраняет 12 радиальных сегментов. Интерактивный viewer использует адаптивную детализацию, потому что при вращении кадр надо перестраивать много раз:

- до 180 FEM-members — 10 сегментов;
- 181…720 — 8;
- более 720 — 6.

Геометрия строится один раз при `setResult()`, а при вращении пересчитывается только проекция. Pointer-move дополнительно ограничен одним `requestAnimationFrame` на кадр.

Для очень большой мачты это позволяет сохранить физические диаметры и крепёж, не превращая интерфейс в тяжёлый CAD-рендерер.

## Границы модели

Ограничения намеренно совпадают с OBJ-моделью:

- нет винтового профиля резьбы;
- нет сварного валика;
- нет фасок и радиусов конкретного производителя;
- концы арматуры не подрезаются автоматически по поверхности гайки;
- локальные пересечения тел допустимы, если расчётная centerline-модель не содержит данных для достоверной фасонной подрезки.

Просмотрщик — визуализация расчётной и физической компоновки, а не производственная CAD-система.

## Проверки

Focused suite:

```bash
npm run test:viewer
```

проверяет:

- общую mesh-схему и статистику объектов;
- фактические смешанные диаметры модулей;
- принадлежность hardware к соседним модулям интерфейса;
- режим без крепежа;
- реальный вызов `CanvasRenderingContext2D.fill()` для polygon faces;
- наличие pointer/wheel/keyboard/reset interaction;
- общий источник `buildDetailedMastModel()` для viewer и OBJ.

Также выполняются:

```bash
npm run test:obj
npm run test:ux
npm test
npm run check
```
