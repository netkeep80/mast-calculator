# Экспорт конструкторской документации по ЕСКД

## Назначение

Бумажный расчётный проект автоматически дополняется комплектом конструкторской документации для рассчитанной модульной мачты. Экспорт остаётся полностью браузерным и не требует backend, CAD-сервера или runtime npm-зависимостей.

Схема данных экспорта: `mast-calculator/eskd-construction-documentation/v1`.

## Нормативная база для РФ

Экспорт ориентирован на действующую в Российской Федерации систему ЕСКД:

- **ГОСТ Р 2.102-2023** — виды и комплектность конструкторских документов;
- **ГОСТ Р 2.104-2023** — основные надписи и дополнительные графы;
- **ГОСТ Р 2.105-2019** — общие требования к текстовым документам;
- **ГОСТ Р 2.109-2023** — основные требования к чертежам;
- **ГОСТ Р 2.201-2023** — обозначение изделий и конструкторских документов;
- **ГОСТ 2.301-68** — форматы листов.

Старые ГОСТ 2.102-2013 и ГОСТ 2.104-2006 не используются как нормативная база российского экспорта: для РФ они заменены национальными стандартами 2023 года, введёнными с 01.03.2024.

## Состав автоматически формируемого комплекта

После разделов расчётного проекта создаются шесть печатных листов формата А4:

1. `Мачта модульная. Сборочный чертеж`;
2. `Мачта модульная. Спецификация`;
3. `Модуль мачты. Сборочный чертеж`;
4. `Модуль мачты. Спецификация`;
5. `Узел межмодульный. Сборочный чертеж`;
6. `Ребро. Чертеж детали`.

Графические листы получают основную надпись формы 1, спецификации — формы 2. Листы формируются как HTML + векторный SVG и рассчитаны на печать/сохранение в PDF из браузера.

Рамка А4 использует поле подшивки 20 мм слева и 5 мм сверху, справа и снизу.

## Single-source принцип

КД не содержит отдельной вручную поддерживаемой копии конструкции. Генератор берёт значения из результата того же расчёта, который показан пользователю:

- число модулей;
- длину и диаметр ребра;
- класс и стандарт арматуры;
- высоту модуля и общую высоту;
- фактически выбранный болт и его класс;
- проходную и длинную гайки;
- катет и расчётную физическую длину сварного шва;
- выбранный сварочный материал;
- производственную оценку массы сборок.

Состав модуля синхронизирован с `assembly-mass-v1`: 9 рёбер, 3 длинные гайки, 3 проходные гайки, 3 болта и 18 сваренных концов.

## Почему обозначения и подписи не заполняются автоматически

ГОСТ Р 2.201-2023 требует, чтобы обозначения изделий и КД присваивала организация-разработчик и чтобы они были уникальными. Калькулятор не знает утверждённый код организации, систему обозначений предприятия, ответственных лиц и полномочия подписантов.

Поэтому генератор намеренно выводит:

- `Обозначение: НЕ ПРИСВОЕНО`;
- пустые поля `Разраб.`, `Провер.`, `Н. контр.`, `Утв.`;
- пустое поле организации-разработчика.

Это безопаснее, чем генерировать правдоподобные, но юридически ложные реквизиты.

Перед выпуском в производство необходимо:

1. присвоить изделиям и КД реальные обозначения по принятой системе организации;
2. заполнить реквизиты и подписи;
3. выполнить нормоконтроль;
4. назначить технологические допуски, которые не следуют из расчётной модели;
5. назначить защитное покрытие для фактических условий эксплуатации;
6. сверить геометрию покупных болтов и гаек с документацией конкретного поставщика;
7. подтвердить применяемую технологию сварки и требования контроля сварных соединений.

## Граница автоматизации

Экспорт — это автоматически сформированный **проект КД**, а не подписанный подлинник и не сертификация изделия.

Калькулятор не должен автоматически придумывать:

- код организации-разработчика;
- уникальные обозначения КД;
- фамилии и подписи;
- не заданные пользователем допуски;
- покрытие;
- технологический процесс изготовления;
- программу контроля и приёмки;
- данные сертификатов конкретных партий материала и крепежа.

Такие сведения зависят от изготовителя, производственной площадки и фактических закупленных изделий.

## Проверки

`tests/eskd-export.test.js` закрепляет следующие контракты:

- нормативный список содержит актуальные российские стандарты и не использует отменённые версии 2.102-2013/2.104-2006 как основную базу;
- экспорт содержит ровно шесть листов А4;
- присутствуют формы основной надписи 1 и 2;
- состав и геометрия переносятся из фактически рассчитанного результата;
- спецификация модуля согласована с production-моделью сборочной массы;
- генератор не подделывает обозначения, организацию и подписи;
- обычный `createCalculationProjectHtml()` действительно включает комплект КД.

Локальная проверка:

```bash
npm test
npm run test:ux
npm run check
```
