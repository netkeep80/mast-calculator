# Требования к Mast Calculator

Статус: рабочая спецификация проекта, прототип 0.6.

## 1. Цель

Mast Calculator — статическое браузерное приложение для расчёта, проверки и последующей оптимизации модульной мачты из одинаковых арматурных октаэдров.

Основные принципы:

1. приложение работает без backend и публикуется на GitHub Pages;
2. пользовательский ввод ориентирован на реальные параметры изготовления и эксплуатации;
3. глобальный расчёт каркаса отделён от будущего расчёта реальных болтовых, резьбовых и сварных узлов;
4. формулы и численные методы должны иметь аналитические, инвариантные и regression-тесты;
5. результат должен быть воспроизводимым и иметь Git SHA расчётного кода;
6. после расчёта формируется человекочитаемый бумажный расчётный проект с формулами и численными подстановками;
7. изменения расчётного ядра проходят обязательную CI/CD-верификацию на трёх ОС.

## 2. Практический ввод

Пользователь задаёт:

- количество модулей;
- закупочную длину прутка;
- число равных частей раскроя;
- диаметр арматуры;
- класс арматуры;
- погодный сценарий либо пользовательское ветровое давление;
- направление/огибающую ветра;
- обледенение;
- массу и парусность оборудования;
- дополнительные нагрузки;
- расчётные коэффициенты и ограничения в расширенном разделе.

Пользователь не вводит вручную:

- длину ребра после выбора раскроя;
- высоту правильного октаэдра;
- `E`, `nu`, `Ry`, `Rm`, плотность стали;
- коэффициент расчётной длины ребра текущей идеализации жёстких концов.

Эти величины вычисляются или берутся из каталогов.

## 3. Геометрия модуля

До учёта ширины реза и реального соединительного узла:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = sqrt(a² - R²) = a*sqrt(2/3)
H = Nmodules*h
```

`a` — длина каждого из девяти рёбер правильного октаэдра.

Нижняя и верхняя равносторонние треугольные грани имеют сторону `a` и повёрнуты друг относительно друга на 60°.

`a` и `h` отображаются readonly. Ручной параметр высоты не должен менять расчётную геометрию.

Пока не учитываются:

- ширина реза;
- торцевая подрезка;
- заход/нахлёст арматуры на узел;
- дополнительная высота гайки/болта;
- смещение расчётных осей внутри реального узла.

После формализации узлов необходимо различать физическую заготовку, полезную длину, осевую FEM-длину и полную физическую высоту модуля.

## 4. Глобальная 3D frame-модель

Глобальная модель отвечает на вопрос:

> выдерживает ли арматурный каркас нагрузки, если все соединения считать идеальными, абсолютно жёсткими и неразрушаемыми?

Реальные болты, гайки, резьба и сварные швы проверяются отдельно.

Жёсткое соединение передаёт:

```text
N
Vy, Vz
T
My, Mz
```

Поэтому основная модель — пространственная Euler–Bernoulli frame FEM:

```text
qnode = [ux, uy, uz, rx, ry, rz]
```

У узла 6 DOF, у frame-element 12 DOF.

Круглое сечение:

```text
A = pi*d²/4
Iy = Iz = pi*d⁴/64
J = pi*d⁴/32
W = pi*d³/32
G = E/[2*(1+nu)]
```

Жёсткости элемента:

```text
EA
EIy
EIz
GJ
```

Три нижних узла текущей модели полностью заделаны:

```text
ux = uy = uz = rx = ry = rz = 0
```

Фундамент в будущем должен стать отдельной параметрической моделью.

## 5. Нагрузки

Эксплуатационный расчёт поддерживает:

- собственный вес стали;
- цилиндрический слой льда;
- ветер на каждое пространственно ориентированное ребро;
- массу оборудования;
- ветер на оборудование;
- дополнительную горизонтальную силу;
- дополнительную вертикальную силу;
- огибающую по направлениям ветра.

Собственный вес, лёд и ветер на ребро задаются распределёнными нагрузками frame-element.

Для цилиндрического ребра ветер использует только нормальную к оси составляющую:

```text
qw_vec = p*cd*dout*gamma_w*[ew - ex*(ex dot ew)]
```

Для равномерной поперечной нагрузки consistent nodal vector должен содержать силы `qL/2` и конечные моменты `qL²/12`.

Текущая огибающая не заменяет нормативный генератор сочетаний.

## 6. Погодные сценарии

UI должен иметь dropdown полной шкалы Бофорта 0–12, включая ураган.

Источник характерных диапазонов/скоростей:

- Met Office Beaufort scale: <https://weather.metoffice.gov.uk/guides/coast-and-sea/beaufort-scale>

Сценарии хранят:

```text
id
Beaufort force
название
диапазон скорости
расчётную скорость v
```

Динамическое давление:

```text
q = rho_air*v²/2
rho_air = 1.225 kg/m³
```

Для Beaufort 12 в прототипе используется нижняя граница урагана `v=33 м/с`.

Обязательно сохраняется режим ручного ввода `windPressurePa`.

Погодные сценарии — только удобный сравнительный инструмент. Они не заменяют СП 20, ветровое районирование, высотные коэффициенты, порывы, пульсацию и нормативные сочетания.

## 7. Проверка рёбер

Для каждого элемента определяются конечные `N/V/T/M`.

Напряжения:

```text
sigma_N = |N|/A
sigma_M = M/W
sigma = sigma_N + sigma_M

tau_T = T*(d/2)/J
tau_V = 4V/(3A)
tau = sqrt(tau_T² + tau_V²)

sigma_eq = sqrt(sigma² + 3*tau²)
eta_sigma = sigma_eq / (Ry/gamma_M)
```

Для равномерной поперечной нагрузки нельзя терять возможный максимум момента между узлами.

Локальная устойчивость сжатого ребра:

```text
Leff = mu*L
N_E = pi²*E*I/Leff²/gamma_M
mu = 0.5
eta_Euler = Ncompression/N_E
```

Итог:

```text
eta_member = max(eta_sigma, eta_Euler)
```

Это инженерная упругая проверка, не полная нормативная проверка по СП 16.

## 8. Общая устойчивость

После статического frame-расчёта строится геометрическая матрица `KG`:

```text
(K + lambda*KG)*phi = 0
```

Необходимо сохранять:

- минимальный положительный `lambda_cr`;
- translational и rotational mode;
- определяющий load case;
- residual/eigenResidual.

Следующие уровни развития:

- P-Delta;
- геометрическая нелинейность;
- начальные несовершенства;
- пластичность.

## 9. Максимальная боковая нагрузка вершины

### 9.1. Назначение

Нужен отдельный параметр, который можно сопоставить с натурным испытанием мачты как консольной стрелы: горизонтальная сила прикладывается к вершине, а программа определяет первый расчётный предел и отдельно силу линейной общей потери устойчивости.

Параметры отображаются в:

```text
N
kN
kgf
```

В интерфейсе должно явно использоваться `кгс`, а не просто `кг`, чтобы не смешивать массу и силу.

### 9.2. Нормированный единичный случай

Отдельный боковой тест задаётся:

```text
F0 = 1 Н horizontal
```

Сила делится поровну между тремя top nodes.

Чтобы результат был воспроизводимым и легко проверялся экспериментом, в этом специальном случае отключаются:

```text
ветер
лёд
собственный вес
оборудование
другие дополнительные нагрузки
```

### 9.3. Предельная сила по ребру

При линейном solver коэффициент использования пропорционален внешней силе:

```text
Fmember = 1 / eta_member(F0=1 N)
```

Определяющий механизм сохраняется как:

```text
material-strength
local-member-buckling
```

### 9.4. Общая устойчивость бокового случая

Если единичная боковая сила создаёт физически значимые сжатые элементы:

```text
Fglobal = lambda_cr(F0=1 N)*1 N
```

Если максимальное осевое сжатие меньше `1e-9 Н`, оно считается машинным шумом и global eigen-buckling для этого конкретного бокового случая не применяется. Это необходимо для чисто поперечной сплошной консоли, у которой теоретически нет предварительного осевого сжатия.

### 9.5. Первый предел

```text
Flim = min(Fmember, Fglobal)
```

Программа должна отдельно показывать:

- `Flim` — первый предел;
- `Fmember`;
- `Fglobal` — боковую силу линейной общей потери устойчивости;
- определяющий механизм;
- направление;
- критическое ребро.

### 9.6. Направления

Из-за вращательной периодичности треугольной мачты проверяется сектор 120°.

Default step:

```text
15°
```

Шаг должен быть настраиваемым.

### 9.7. Интерпретация

`Flim` и `Fglobal` — характеристики идеальной линейной frame-модели и проверочного лабораторного сценария. Это не допустимая рабочая грузоподъёмность подъёмного механизма.

Натурное испытание имеет собственный вес, несовершенства, конечную жёсткость реальных узлов и геометрическую нелинейность.

## 10. Solid-rod sanity-check

Для независимой проверки порядка величин нужен автоматический тест предельной геометрии:

```text
d_rib = a/2
```

Габаритный диаметр мачты:

```text
D = 2a/sqrt(3)
```

Сравнительная модель:

```text
solid circular cantilever
height = H_mast
diameter = D
same E, nu, Ry
same fixed base
same unit lateral tip load
```

Площадь шести рёбер:

```text
A6 = 6*pi*(a/2)²/4
```

Площадь solid rod:

```text
Asolid = pi*(2a/sqrt(3))²/4
```

Инвариант:

```text
A6/Asolid = 9/8 = 1.125
```

Regression test должен сравнивать два независимых показателя:

```text
P_mast / P_solid
K_mast / K_solid, where K=F/delta
```

Цель — не искусственное равенство решётки и сплошного стержня, а обнаружение ошибок масштаба, единиц, жёсткости или топологии. Допустимые sanity bands фиксируются в тесте и документации.

Подробности: [`LATERAL_CAPACITY_WEATHER_VALIDATION.md`](LATERAL_CAPACITY_WEATHER_VALIDATION.md).

## 11. Аналитические тесты боковой проверки

Для круглой консоли под поперечной концевой силой `P` solver использует одновременно максимальное изгибное напряжение и поперечный срез:

```text
A = pi*d²/4
W = pi*d³/32
sigma_M = P*L/W
tau_V = 4P/(3A)
sigma_eq = sqrt((P*L/W)² + 3*(4P/(3A))²)
```

При `sigma_eq = Ryd` аналитический предел:

```text
P_y = Ryd / sqrt((L/W)² + 3*(4/(3A))²)
```

Нормированный алгоритм `1 Н` должен воспроизводить именно это значение до установленного численного допуска.

Упрощённая формула чистого изгиба

```text
P_y,bending = Ryd*W/L
```

допускается только как дополнительная оценка при пренебрежимо малом влиянии поперечного среза и не является эталоном regression-test.

Существующие аналитические проверки frame solver также обязательны:

```text
delta_axial = F*L/(E*A)
delta_cantilever = P*L³/(3*E*I)
theta_cantilever = P*L²/(2*E*I)
fixed-fixed reactions = qL/2
fixed-fixed moments = qL²/12
```

## 12. Реальные соединительные узлы

Для каждого физического соединения и каждого реального load case будущий joint module должен получать связанный набор:

```text
N
Vy
Vz
T
My
Mz
loadCaseId
```

Нельзя составлять искусственный vector demand из независимых максимумов разных случаев.

Будущий узловой расчёт должен учитывать:

- болт/шпильку на растяжение и срез;
- совместное действие;
- наружную/внутреннюю резьбу;
- длину зацепления;
- смятие;
- гайку;
- сварную группу;
- основной металл;
- эксцентриситеты и моменты;
- процесс, марку и диаметр сварочного материала.

Результат:

```text
PASS / FAIL
demand
resistance
utilization
governing failure mode
fastener/weld specification
```

## 13. Каталоги

Арматура первого этапа:

```text
A400C
A500C
A600C
ГОСТ 34028-2016
```

Каталог централизованно хранит `E`, `nu`, `Ry`, `Rm`, плотность, свариваемость и источник.

Будущие каталоги болтов/резьбы/сварки должны хранить нормативный источник и редакцию данных.

## 14. Бумажный расчётный проект

Пользовательский автономный HTML должен быть пригоден для передачи инженеру и печати/PDF.

Он показывает:

1. method id и Git SHA;
2. исходные данные;
3. раскрой и геометрию октаэдра;
4. `A/I/J/W/G`;
5. формулы собственного веса, льда и ветра;
6. погодный preset, `v` и `q=rho*v²/2`;
7. frame element и `K*u=F`;
8. `N/V/T/M` определяющего ребра;
9. напряжения;
10. локальный Эйлер;
11. global eigen-buckling;
12. боковые `Fmember`, `Fglobal`, `Flim` с численной подстановкой;
13. таблицы эксплуатационных и боковых направлений;
14. diagnostics;
15. ограничения модели.

Генератор документа не имеет права повторно выполнять FEM. Он читает готовый result object и делает только форматирование/подстановки.

В бумажном проекте нет JSON dump.

## 15. Internal CalculationSnapshot

Внутренний `CalculationSnapshot v4` нужен для regression/cross-check и отладки.

Он должен содержать:

- method/schema/Git SHA;
- resolved parameters, включая weather preset;
- nodes/members/restraints;
- все эксплуатационные load cases;
- displacements/rotations/reactions;
- member results;
- global buckling;
- lateral capacity cases;
- diagnostics.

Snapshot не показывается отдельной пользовательской кнопкой и не встраивается в бумажный проект.

## 16. Верификация

### 16.1. Аналитика

Обязательные задачи:

- `FL/(EA)`;
- `PL³/(3EI)`;
- `PL²/(2EI)`;
- fixed-fixed `qL/2`, `qL²/12`;
- отсутствие паразитных `V/M/T` в axial case;
- аналитические eigensystems;
- полная von Mises формула боковой консоли из раздела 11;
- `q=rho*v²/2` и обратное преобразование.

### 16.2. Инварианты/regression

- равновесие сил и моментов;
- равенство девяти рёбер октаэдра;
- зеркальное чередование модулей;
- coordinate rotation invariance;
- полный Beaufort 0..12;
- монотонность давления по preset;
- solid-rod area ratio `9/8`;
- comparable-order solid-rod force/stiffness;
- UI/report contracts;
- отсутствие пользовательского JSON export.

### 16.3. Independent cross-check

До окончательного практического применения нужны reference models из независимого КЭ-комплекса:

- одиночный beam;
- пространственная рама;
- один модуль;
- два зеркальных модуля;
- полная мачта;
- несимметричный ветер;
- общая потеря устойчивости.

Допуски отдельно фиксируются по `u`, reactions, `N/V/T/M`, stresses и eigenvalues.

## 18. Нормативная база

Как источники данных и будущих нормативных проверок зафиксированы:

- ГОСТ 34028-2016 — арматурный прокат;
- ГОСТ ISO 898-1-2014 — болты, винты и шпильки;
- ГОСТ 24705-2004 — метрическая резьба;
- СП 16.13330.2017 — стальные конструкции и соединения;
- ГОСТ 5264-80 — ручная дуговая сварка;
- ГОСТ 9467-75 — покрытые электроды;
- СП 20.13330.2016 — нагрузки и воздействия;
- ГОСТ 27751-2014 — надёжность конструкций.

Само упоминание документа не означает, что прототип уже реализует все его нормативные проверки.
