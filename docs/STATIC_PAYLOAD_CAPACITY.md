# Максимальная статическая нагрузка на вершине

Этот расчёт добавлен для issue #11: требуется оценить, какую **суммарную массу груза на верхней треугольной грани** может нести мачта, например массу бака с водой.

## Что именно считается

Специальный расчётный случай является gravity-only:

```text
включено:
  собственный вес арматурного каркаса
  искомая вертикальная масса на вершине

исключено:
  ветер
  лёд
  горизонтальные силы
  дополнительные нагрузки из обычного погодного случая
```

Собственный вес принципиально не обнуляется: это не чистый unit-test, а оценка доступной вертикальной грузоподъёмности уже существующего каркаса.

Искомая масса прикладывается вертикально вниз и поровну распределяется между тремя верхними узлами.

## Коэффициенты

Собственный вес стержней используется с существующим коэффициентом постоянной нагрузки:

```text
γg = deadLoadFactor
```

Искомая масса на вершине использует тот же коэффициент, что и масса оборудования:

```text
γpayload = equipmentLoadFactor
```

Для номинальной массы `m`:

```text
Pnom = m·g
Pdesign = m·g·γpayload

g = 9.80665 m/s²
```

UI показывает именно **номинальную массу в килограммах**, а рядом расчётный предел связан с коэффициентами нагрузки.

## Почему нельзя просто масштабировать 1 кг

Если полностью отключить собственный вес, линейная frame-модель действительно позволяет получить чистый предел по расчёту 1 кг:

```text
m_member,pure = 1 / U(1 kg)
m_global,pure = λcr(1 kg)
m_pure = min(m_member,pure, m_global,pure)
```

Но реальная мачта уже нагружена собственным весом. Поэтому `m_pure` используется только как верхняя граница поиска.

Финальная задача решается для состояния

```text
KG(m) = KG_self + KG_payload(m)
```

и для каждого пробного `m` повторно проверяются:

```text
U_member(m) <= 1
λcr(m) >= 1
```

где `λcr(m)` вычисляется из той же линейной eigen-buckling задачи:

```text
(K + λ·KG(m))·φ = 0
```

Условие `λcr = 1` соответствует достижению критического состояния для фактически приложенной комбинации собственного веса и груза.

## Поиск предела

Алгоритм:

1. рассчитывает чистый случай 1 кг без собственного веса и получает безопасную верхнюю границу;
2. проверяет мачту только под собственным весом;
3. проверяет верхнюю границу уже вместе с собственным весом;
4. выполняет 18 итераций двоичного поиска;
5. сохраняет последнюю проходящую массу как безопасную сторону найденного предела.

Во всех итерациях используется одна и та же заранее собранная и факторизованная матрица упругой жёсткости `K`. Меняются только load vector, member actions и `KG`.

## Определяющий механизм

На каждом шаге сравниваются два независимых критерия.

Первый — коэффициент использования наиболее нагруженного ребра:

```text
U_member = max(U_vonMises, U_Euler)
```

Второй — общая устойчивость:

```text
U_global = 1 / λcr
```

Расчётный предел:

```text
max(U_member, U_global) = 1
```

Результат сообщает один из механизмов:

```text
material-strength
local-member-buckling
global-buckling
self-weight-overlimit
```

## Уже установленное оборудование

`maximumTotalTopMassKg` — это максимальная **суммарная** эквивалентная масса на вершине.

Чтобы показать, сколько можно добавить к уже введённым в UI нагрузкам, рассчитывается эквивалент существующей вертикальной нагрузки:

```text
m_existing = equipmentMassKg
           + extraVerticalLoadN / (g·equipmentLoadFactor)
```

и остаток:

```text
m_remaining = max(0, m_max - m_existing)
```

Таким образом, если на вершине уже стоит оборудование, UI показывает не только общий предел, но и фактический остаток для дополнительного груза.

## Эквивалентный объём воды

Для наглядной задачи водонапорной башни используется инженерное округление:

```text
ρwater = 1000 kg/m³
Vwater = m_remaining / ρwater
```

Программа показывает одновременно:

```text
kg
m³
liters
```

Это объём воды по массе. Масса самого бака должна либо входить в `equipmentMassKg`, либо вычитаться из полученного резерва.

## Что результат не учитывает

`maximumTotalTopMassKg` нельзя интерпретировать как готовую паспортную грузоподъёмность водонапорной башни.

Не учтены:

- ветровая площадь и аэродинамический момент самого бака;
- эксцентриситет центра тяжести бака;
- динамическое движение воды и плескание;
- геометрическая нелинейность/P-Delta;
- начальная кривизна и монтажные несовершенства;
- конечная жёсткость реальных соединений;
- болты, резьба, гайки и сварные швы;
- реальный фундамент;
- нормативные сочетания нагрузок.

Поэтому статический результат — отдельная характеристика вертикального гравитационного резерва идеализированной frame-модели. Для реальной водонапорной башни его необходимо сочетать с ветровым и конструктивным расчётом.

## Regression checks

Автоматические тесты проверяют:

- конечность и положительность найденной массы;
- наличие собственного веса в специальном сценарии;
- безопасную сторону двоичного поиска;
- `U <= 1` и `λcr >= 1` на сохранённом пределе;
- правильный вычет уже существующей вертикальной нагрузки;
- перевод массы в м³ и литры воды;
- независимость специального gravity-only результата от параметров ветра и льда;
- рост грузоподъёмности при увеличении диаметра арматуры;
- полный progress до 100%;
- включение статической фазы в 40-модульный performance regression.
