# Требования к Mast Calculator

Статус: рабочая спецификация проекта.

## 1. Цель

Mast Calculator — статическое браузерное приложение для расчёта, проверки и последующей оптимизации модульной мачты из одинаковых арматурных октаэдров.

Основные принципы:

1. приложение должно работать без backend и публиковаться на GitHub Pages;
2. обычный пользовательский ввод ориентирован на изготовителя/сборщика;
3. глобальный расчёт арматурного каркаса отделён от расчёта реальных болтовых/резьбовых/сварных узлов;
4. расчётные формулы и численные методы должны быть тестируемы и воспроизводимы;
5. после расчёта должен формироваться человекочитаемый бумажный расчётный проект с пошаговыми формулами;
6. изменения расчётного ядра проходят обязательную CI/CD-верификацию.

## 2. Практический ввод арматуры

В обычном режиме пользователь задаёт:

- количество модулей;
- закупочную длину прутка — на первом этапе 11,8 м или 12 м;
- на сколько равных частей разрезать пруток;
- номинальный диаметр арматуры — из выпадающего списка стандартных типоразмеров;
- класс арматуры — из каталога материалов с гарантированной свариваемостью;
- нагрузки и параметры оборудования.

Пользователь **не вводит вручную**:

- длину ребра после выбора раскроя;
- высоту октаэдра;
- модуль упругости;
- коэффициент Пуассона;
- предел текучести;
- временное сопротивление;
- плотность стали;
- коэффициент расчётной длины ребра для текущей идеализации жёстких концов.

Эти значения вычисляются или берутся из каталогов.

## 3. Геометрия модуля

### 3.1. Длина ребра

До учёта ширины реза и геометрии реального узла:

```text
a = Lstock / nparts
```

где:

- `Lstock` — закупочная длина прутка;
- `nparts` — число равных частей;
- `a` — длина каждого из девяти рёбер модуля.

`a` отображается только для чтения.

### 3.2. Правильный октаэдр

Модуль принимается правильным октаэдром. Нижняя и верхняя равносторонние треугольные грани имеют сторону `a` и повернуты друг относительно друга на 60°.

Радиус описанной окружности треугольной грани:

```text
R = a / sqrt(3)
```

Высота между треугольными гранями:

```text
h = sqrt(a² - R²) = a * sqrt(2/3)
```

Высота `h` является **производным readonly-параметром**. Отдельного ручного поля высоты модуля быть не должно.

Расчётная высота мачты без соединительных узлов:

```text
H = Nmodules * h
```

### 3.3. Что пока не входит в геометрию

В версии 0.5 пока не учитываются:

- ширина реза;
- торцевая подрезка;
- фактический заход/нахлёст арматуры на гайку или болт;
- высота соединительного узла между соседними модулями;
- смещение расчётных осей внутри реальной гайки/болта.

После формализации узла необходимо строго различать:

```text
длина закупочного прутка
длина физической заготовки
длина арматуры между границами узла
расчётная осевая длина frame-элемента
общая высота физического модуля с соединительным узлом
```

## 4. Глобальный расчёт арматурного каркаса

### 4.1. Разделение ответственности

Глобальная модель отвечает на вопрос:

> выдерживает ли арматурный каркас нагрузки, если все его узлы считать идеальными, абсолютно жёсткими и неразрушаемыми?

Прочность конкретных болтов, гаек, резьбы и сварных швов не должна снижать или изменять глобальную FEM-модель. Эти элементы проверяются отдельно после получения усилий из каркаса.

### 4.2. Жёсткое соединение рёбер

Фраза «рёбра сварены намертво» означает передачу:

- продольной силы `N`;
- поперечных сил `Vy`, `Vz`;
- крутящего момента `T`;
- изгибающих моментов `My`, `Mz`.

Поэтому шарнирная truss-модель с тремя поступательными степенями свободы недостаточна.

Основная модель версии 0.5 — пространственная Euler–Bernoulli frame-модель:

```text
qnode = [ux, uy, uz, rx, ry, rz]
```

Каждый узел имеет 6 степеней свободы.

### 4.3. Сечение круглой арматуры

Для номинального диаметра `d`:

```text
A = pi*d²/4
Iy = Iz = pi*d⁴/64
J = pi*d⁴/32
W = I/(d/2) = pi*d³/32
G = E/[2*(1+nu)]
```

Frame-element учитывает:

```text
EA
EIy
EIz
GJ
```

### 4.4. Закрепление основания

Три нижних узла глобальной модели на текущем этапе считаются полностью заделанными:

```text
ux = uy = uz = rx = ry = rz = 0
```

В дальнейшем фундамент должен стать отдельной параметрической моделью.

## 5. Нагрузки

Минимальный набор:

- собственный вес арматуры;
- обледенение;
- ветер на каждое пространственно ориентированное ребро;
- масса оборудования;
- ветер на оборудование;
- дополнительная горизонтальная нагрузка;
- дополнительная вертикальная нагрузка;
- огибающая по направлениям ветра.

### 5.1. Распределённые нагрузки

Собственный вес, лёд и ветер на ребро должны задаваться как распределённые нагрузки frame-элемента, а не как искусственные сосредоточенные силы без конечных моментов.

Для цилиндрического ребра ветер учитывает только нормальную составляющую:

```text
qw_vec = p * cd * dout * gamma_w * [ew - ex*(ex dot ew)]
```

где `ex` — ось ребра, `ew` — направление ветра.

### 5.2. Сочетания

Текущая огибающая по направлениям ветра не заменяет полный нормативный генератор сочетаний. Сочетания по выбранной нормативной базе должны быть добавлены отдельным этапом.

## 6. Проверка рёбер

Для каждого frame-element определяются конечные усилия и моменты.

### 6.1. Напряжения

Используются:

```text
sigma_N = |N|/A
sigma_M = M/W
sigma = sigma_N + sigma_M

tau_T = T*(d/2)/J
tau_V = 4V/(3A)
tau = sqrt(tau_T² + tau_V²)

sigma_eq = sqrt(sigma² + 3*tau²)
```

Проверка по текущей упругой модели:

```text
eta_sigma = sigma_eq / (Ry/gamma_M)
```

При равномерной поперечной нагрузке необходимо учитывать возможность максимума изгибающего момента между узлами, а не только конечные моменты.

### 6.2. Локальная устойчивость

Дополнительная проверка отдельного сжатого ребра:

```text
N_E = pi²*E*I / (mu*L)² / gamma_M
```

Для идеализированных абсолютно жёстких концов текущая модель использует:

```text
mu = 0.5
```

Итоговое использование ребра:

```text
eta = max(eta_sigma, eta_Euler)
```

Это пока инженерная упругая проверка, а не полная нормативная проверка устойчивости по СП 16.

## 7. Общая устойчивость

После статического frame-расчёта собирается геометрическая матрица жёсткости `KG`.

Линейная задача общей потери устойчивости:

```text
(K + lambda*KG) * phi = 0
```

Необходимо сохранять:

- минимальный положительный `lambda_cr`;
- форму потери устойчивости;
- определяющий расчётный случай;
- невязку собственной задачи.

Следующий уровень развития:

- геометрически нелинейный расчёт;
- начальные несовершенства;
- `P-Delta`;
- пластичность при необходимости.

## 8. Отдельный расчёт реального узла

### 8.1. Demand из глобальной модели

Для каждого физического соединения и каждого реального расчётного случая необходимо передавать:

```text
N
Vy
Vz
T
My
Mz
loadCaseId
```

Нельзя составлять физически несуществующий load vector из независимых максимумов разных расчётных случаев. Любой экстремум должен сохранять ссылку на исходный совместный набор `N/V/T/M`.

### 8.2. Параметры узла

Будущий узловой модуль должен учитывать:

- тип узла;
- номинальную метрическую резьбу;
- шаг резьбы;
- класс прочности болта/шпильки;
- материал гайки/соединительной гайки;
- длину резьбового зацепления;
- число плоскостей среза;
- положение арматуры относительно оси узла;
- число сварных швов;
- длину и катет каждого шва;
- пространственное положение швов;
- способ сварки;
- марку и диаметр электрода/сварочной проволоки;
- материалы соединяемых деталей.

### 8.3. Проверки узла

Минимально:

- болт/шпилька на растяжение;
- болт/шпилька на срез;
- совместное действие растяжения и среза;
- наружная и внутренняя резьба;
- длина зацепления;
- смятие;
- гайка/соединительная гайка;
- сварная группа по металлу шва;
- сварная группа по границе сплавления;
- основной металл около шва;
- эксцентриситет;
- действие моментов на сварную группу.

Результат:

```text
PASS / FAIL
фактический demand
расчётная resistance
коэффициент использования
определяющий механизм
спецификация крепежа и сварки
```

## 9. Каталоги материалов

### 9.1. Арматура

На первом этапе:

- А400С;
- А500С;
- А600С;
- ГОСТ 34028-2016.

Каталог хранит централизованно:

- `E`;
- `nu`;
- `Ry`;
- `Rm`;
- плотность;
- признак гарантированной свариваемости;
- нормативный источник.

### 9.2. Болты и резьба

Будущий каталог должен хранить данные с указанием источника и редакции стандарта, а не безымянные таблицы «разрушающих нагрузок».

### 9.3. Сварка

Выбор сварочного материала должен зависеть как минимум от:

- процесса сварки;
- основного металла;
- типа соединения;
- расчётной температуры;
- требуемых свойств металла шва.

Марку и диаметр электрода/проволоки нельзя назначать только по диаметру арматуры.

## 10. Бумажный расчётный проект

После расчёта приложение формирует автономный HTML-документ, пригодный для:

- передачи инженеру-конструктору;
- печати на бумаге;
- сохранения браузером в PDF.

Это **не JSON dump** и не машинный протокол.

Документ должен пошагово показывать:

1. идентификатор версии расчётного метода и Git SHA;
2. все исходные данные;
3. получение длины ребра из закупочного прутка;
4. вывод высоты правильного октаэдра;
5. вычисление `A`, `I`, `J`, `W`, `G`;
6. формулы собственного веса, льда и ветра;
7. принцип формирования frame-element и `K*u=F`;
8. формулы напряжений `N/V/T/M`;
9. численную подстановку для определяющего ребра;
10. локальную проверку Эйлера;
11. общую eigen-buckling проверку;
12. таблицу расчётных случаев;
13. ведомость всех рёбер;
14. численные невязки;
15. ограничения текущей модели.

Генератор бумажного документа **не имеет права заново выполнять FEM-расчёт**. Он только читает уже полученные результаты и форматирует их.

## 11. Внутренняя воспроизводимость

Для автоматических тестов и отладки допускается внутренний канонический `CalculationSnapshot` с полной геометрией, нагрузками и результатами.

Он:

- не является пользовательским бумажным отчётом;
- не показывается отдельной кнопкой в UI;
- не встраивается в бумажный расчётный проект;
- нужен для regression/cross-check тестов и машинного сравнения версий.

## 12. Верификация расчётного ядра

Для каждого существенного численного метода обязательны три слоя.

### 12.1. Аналитические тесты

Минимум:

- осевое растяжение: `delta = FL/(EA)`;
- консоль с поперечной силой: `delta = PL³/(3EI)`;
- поворот конца консоли: `theta = PL²/(2EI)`;
- жёстко заделанная с двух сторон балка под равномерной нагрузкой: реакции `qL/2`, моменты `qL²/12`;
- чистый осевой случай без паразитных `V/M/T`;
- аналитические собственные значения для базового eigensolver.

### 12.2. Инварианты

- равновесие сил;
- равновесие моментов;
- симметрия геометрии;
- одинаковая длина всех девяти рёбер правильного октаэдра;
- инвариантность балочного результата к повороту глобальной системы координат;
- отсутствие ручного влияния на производную высоту модуля;
- отсутствие скрытого JSON в бумажном отчёте.

### 12.3. Cross-check

До практического применения результаты должны быть сверены с независимым КЭ-комплексом.

Эталонный набор:

- одиночный beam;
- простая пространственная рама;
- один октаэдр;
- два зеркально ориентированных модуля;
- полная мачта;
- несимметричный ветер;
- общая потеря устойчивости.

Для каждого эталона фиксируются допустимые расхождения отдельно по:

- перемещениям;
- реакциям;
- `N/V/T/M`;
- напряжениям;
- собственным значениям.

## 13. CI/CD требования

Подробный аудит: [`CI_CD_REVIEW.md`](CI_CD_REVIEW.md).

Обязательные инварианты:

- `npm test` на каждом PR с расчётными изменениями;
- тестовая матрица Linux/macOS/Windows;
- explicit timeout для каждого job;
- least-privilege token permissions;
- fresh-merge simulation относительно актуального `main`;
- secret scan;
- syntax checks;
- file line limit guard;
- smoke-test статического сайта;
- tests для самих workflow policy;
- Pages deploy только после успешной повторной проверки;
- writer deployment не отменяется посередине новым push;
- опубликованный Git SHA доступен генератору расчётного проекта.

## 14. Нормативная база

На текущем этапе в проекте должны учитываться как источники данных и будущих проверок:

- ГОСТ 34028-2016 — арматурный прокат;
- ГОСТ ISO 898-1-2014 — механические свойства болтов, винтов и шпилек;
- ГОСТ 24705-2004 — основные размеры метрической резьбы;
- СП 16.13330.2017 — стальные конструкции и соединения;
- ГОСТ 5264-80 — ручная дуговая сварка, типы и конструктивные элементы соединений;
- ГОСТ 9467-75 — покрытые электроды для конструкционных сталей;
- СП 20.13330.2016 — нагрузки и воздействия;
- ГОСТ 27751-2014 — надёжность строительных конструкций и оснований.

Конкретная редакция/изменение нормативного документа должна фиксироваться в той версии расчётного метода, где соответствующая нормативная проверка реализована.

Само наличие названия стандарта в проекте не означает, что версия 0.5 уже реализует все его требования.

## 15. Порядок дальнейшей реализации

1. Стабилизировать и независимо проверить 3D frame solver версии 0.5.
2. Добавить reference/cross-check модели из внешнего КЭ-комплекса.
3. Формализовать геометрию реального соединительного узла и поправку физической длины/высоты.
4. Сформировать `N/V/T/M` demand envelope для физических узлов.
5. Добавить каталог болтов, резьбы, гаек и сварочных материалов.
6. Реализовать расчёт реальных узлов.
7. Добавить нормативные сочетания нагрузок.
8. Добавить геометрическую нелинейность и начальные несовершенства.
9. Реализовать оптимизацию массы, стоимости и раскроя.
