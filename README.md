# Mast Calculator

Статическое веб-приложение для расчёта модульной телекоммуникационной мачты из сварных арматурных октаэдров. Сервер не требуется: расчёт выполняется непосредственно в браузере, приложение публикуется через GitHub Pages.

Опубликованная версия:

**https://netkeep80.github.io/mast-calculator/**

Документация:

- [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) — требования и расчётные допущения;
- [`docs/CALCULATION_ARCHITECTURE.md`](docs/CALCULATION_ARCHITECTURE.md) — архитектура FEM и отчётности;
- [`docs/CI_CD_REVIEW.md`](docs/CI_CD_REVIEW.md) — аудит CI/CD по шаблонам link-foundation.

## Прототип 0.5

### Практический ввод

Пользователь задаёт реальные производственные параметры:

- количество модулей;
- закупочную длину арматуры 11,8 или 12 м;
- на сколько равных частей режется один пруток;
- номинальный диаметр арматуры из выпадающего списка;
- класс арматуры `А400С`, `А500С` или `А600С`;
- нагрузки и параметры оборудования.

Механические свойства материала берутся из каталога. Длина ребра и высота модуля вручную не вводятся.

## Геометрия правильного октаэдра

До учёта ширины реза, соединительного узла и нахлёста арматуры:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = a * sqrt(2/3)
H = Nmodules * h
```

где `a` — длина каждого из девяти рёбер модуля, `h` — расстояние между его треугольными гранями.

Например, для прутка 12 м, разрезанного на 16 частей:

```text
a = 750 мм
h = 612,372 мм
```

Все девять рёбер каждого модуля проверяются тестами на равенство длины.

## Расчётное ядро

Начиная с 0.5 глобальная модель — не шарнирная ферма, а пространственная **3D Euler–Bernoulli frame FEM** с идеально жёсткими сварными узлами.

Каждый узел имеет шесть степеней свободы:

```text
[ux, uy, uz, rx, ry, rz]
```

Каждое круглое ребро учитывает:

```text
EA   — осевую жёсткость
EIy  — изгибную жёсткость
EIz  — изгибную жёсткость
GJ   — крутильную жёсткость
```

Расчёт возвращает для рёбер не только продольные силы, но и:

```text
N
Vy, Vz
T
My, Mz
```

а также перемещения, повороты узлов, реакции и реактивные моменты.

## Нагрузки

Реализованы:

- собственный вес арматуры;
- цилиндрический слой льда;
- ветер на каждое пространственно ориентированное ребро;
- масса оборудования;
- ветер на оборудование;
- дополнительные горизонтальная и вертикальная нагрузки;
- огибающая по направлениям ветра.

Собственный вес, лёд и ветер на ребро моделируются как распределённые нагрузки frame-element. Для равномерной поперечной нагрузки consistent nodal vector содержит не только силы `qL/2`, но и конечные моменты `qL²/12`.

Для цилиндрического ребра учитывается только составляющая ветра, нормальная к его оси.

## Проверка рёбер

Для круглого сечения используются:

```text
A = pi*d²/4
I = pi*d⁴/64
J = pi*d⁴/32
W = I/(d/2)
```

Упругая проверка учитывает осевое усилие, изгиб, поперечный срез и кручение. Эквивалентное напряжение рассчитывается по фон Мизесу.

Дополнительно сжатое ребро проверяется по Эйлеру. Для текущей идеализации абсолютно жёстких концов:

```text
mu = 0.5
N_E = pi² E I / (mu L)² / gamma_M
```

Итоговый коэффициент использования ребра — максимум проверки напряжений и локальной устойчивости.

## Общая устойчивость

После статического frame-расчёта собирается геометрическая матрица жёсткости `K_G` и решается линейная собственная задача:

```text
(K + lambda K_G) phi = 0
```

Приложение показывает минимальный критический множитель и первую форму общей потери устойчивости.

## Реальные соединительные узлы

Глобальная FEM-модель сознательно считает узлы идеальными и неразрушаемыми. Реальные соединения будут проверяться отдельным модулем по demand из глобального расчёта:

```text
N, Vy, Vz, T, My, Mz
```

В отдельный расчёт войдут:

- болт/шпилька;
- метрическая резьба и длина зацепления;
- гайка/соединительная гайка;
- сварная группа;
- основной металл;
- марка и диаметр электрода/сварочной проволоки;
- эксцентриситеты.

## Бумажный расчётный проект

Кнопка **«Скачать расчётный проект»** формирует автономный HTML-документ, предназначенный для передачи инженеру и печати/сохранения в PDF.

Он пошагово показывает:

1. исходные данные и Git SHA расчётного кода;
2. получение длины ребра из закупочного прутка;
3. вывод высоты правильного октаэдра;
4. `A`, `I`, `J`, `W`, `G`;
5. формулы собственного веса, льда и ветра;
6. устройство 3D frame-element и уравнение `K u = F`;
7. численную подстановку `N/V/T/M` для определяющего ребра;
8. расчёт напряжений;
9. локальную проверку Эйлера;
10. расчёт общей устойчивости;
11. таблицы расчётных случаев и всех рёбер;
12. численные невязки и ограничения модели.

В бумажном проекте **нет JSON**. Внутренний `CalculationSnapshot` остаётся только средством regression/cross-check тестирования и отладки.

## Верификация

Расчётное ядро проверяется несколькими слоями тестов.

Аналитические задачи включают:

- растяжение `delta = FL/(EA)`;
- консоль `delta = PL³/(3EI)`;
- поворот консоли `theta = PL²/(2EI)`;
- жёстко заделанную с двух сторон балку под `q` — реакции `qL/2` и моменты `qL²/12`;
- собственные значения тестовых матриц.

Инварианты включают:

- равновесие сил и моментов;
- поворотную инвариантность frame-element;
- одинаковую длину девяти рёбер правильного октаэдра;
- правильное зеркальное чередование модулей;
- контракты UI и бумажного отчёта;
- policy тесты самих GitHub workflows.

До использования как окончательного инженерного инструмента требуется cross-check с независимым КЭ-комплексом на эталонных моделях.

## CI/CD

CI/CD пересмотрен по актуальным шаблонам:

- `link-foundation/js-ai-driven-development-pipeline-template`;
- `link-foundation/rust-ai-driven-development-pipeline-template`;
- `link-foundation/python-ai-driven-development-pipeline-template`;
- `link-foundation/csharp-ai-driven-development-pipeline-template`.

В PR выполняются:

```text
Syntax, policy and maintainability
Secrets scan
Tests — Ubuntu
Tests — macOS
Tests — Windows
Static site smoke test
```

Применены:

- `actions/checkout@v6`;
- `actions/setup-node@v6`, Node.js 24.x;
- explicit job timeouts;
- least-privilege permissions;
- fresh-merge simulation с актуальным `main`;
- secretlint;
- ограничение размера исходных файлов;
- cross-platform test matrix;
- автоматические тесты policy GitHub Actions;
- безопасная serialized Pages publication.

Pages использует официальный artifact flow:

```text
actions/configure-pages@v6
actions/upload-pages-artifact@v5
actions/deploy-pages@v5
```

Перед публикацией повторно запускаются тесты и проверки. SHA опубликованного коммита записывается в `build-info.json` и попадает в бумажный расчётный проект.

## Нормативные источники

Проект фиксирует источники будущих нормативных проверок, в частности:

- ГОСТ 34028-2016 — арматурный прокат;
- ГОСТ ISO 898-1-2014 — болты, винты и шпильки;
- ГОСТ 24705-2004 — метрическая резьба;
- СП 16.13330.2017 — стальные конструкции и соединения;
- ГОСТ 5264-80 — ручная дуговая сварка;
- ГОСТ 9467-75 — покрытые электроды;
- СП 20.13330.2016 — нагрузки и воздействия;
- ГОСТ 27751-2014 — надёжность строительных конструкций.

Упоминание стандарта не означает, что прототип 0.5 уже реализует все его нормативные проверки.

## Ограничения 0.5

Пока не реализованы:

- геометрия и дополнительная высота реального соединительного узла;
- ширина реза и нахлёст арматуры;
- нормативный расчёт болтов, резьбы, гаек и сварных швов;
- полноценные нормативные сочетания нагрузок;
- геометрическая нелинейность и начальные несовершенства;
- усталость;
- параметрический фундамент;
- независимые reference-results из внешнего КЭ-комплекса.

## Локальный запуск

```bash
python3 -m http.server 8080 --directory site
```

Открыть `http://localhost:8080`.

Проверки:

```bash
npm test
npm run check
node scripts/check-file-line-limits.mjs
```

У проекта нет runtime npm-зависимостей; Node.js используется как test runner и для CI utility scripts.

## Единицы

Внутри расчётного ядра используются SI: метры, ньютоны, паскали, радианы и килограммы. UI и бумажный проект преобразуют значения в удобные инженерные единицы на границе системы.
