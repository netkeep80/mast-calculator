# Разные диаметры арматуры по ярусам

Issue #22 добавляет в одну мачту физические модули из арматуры разного диаметра. Основной практический сценарий — оставить более толстые и жёсткие модули внизу, где усилия обычно выше, и уменьшать диаметр к вершине. Это может уменьшить массу стали и ветровую нагрузку на верхние ярусы, но пригодность конкретного профиля всегда определяется полным FEM-расчётом, а не правилом «чем выше, тем тоньше».

## Пользовательский ввод

В форме есть два режима:

- **один диаметр для всех модулей** — прежнее поведение, полностью совместимое с предыдущими версиями;
- **разные диаметры по модулям** — отдельный стандартный диаметр для каждого физического октаэдра.

Модули нумеруются **снизу вверх**: модуль 1 опирается на фундамент, последний модуль является верхним.

В расчётном API профиль передаётся как:

```js
{
  moduleCount: 6,
  barDiameterMm: 12,
  moduleDiametersMm: [20, 20, 16, 16, 12, 10]
}
```

`barDiameterMm` остаётся обратносуместимым единым значением по умолчанию. Если `moduleDiametersMm` отсутствует, все модули используют `barDiameterMm`.

## Правило длины профиля

Для текущей высоты берутся первые `moduleCount` значений профиля.

Если дискретный поиск максимальной высоты проверяет больше модулей, чем явно задано в `moduleDiametersMm`, новые верхние модули получают **последний, то есть верхний, диаметр профиля**. Например:

```text
задан профиль:       Ø20, Ø16, Ø12
trial 2 modules:     Ø20, Ø16
trial 5 modules:     Ø20, Ø16, Ø12, Ø12, Ø12
```

Это правило делает поиск высоты детерминированным. Оно не является автоматической оптимизацией новых верхних ярусов.

## Геометрия и FEM

Каждый physical module по-прежнему содержит 9 рёбер:

```text
3 ребра верхнего треугольника
6 диагональных ножек
```

Все девять рёбер модуля получают его `diameterMm`. Поэтому для каждого стержня независимо меняются:

```text
A = πd²/4
I = πd⁴/64
J = πd⁴/32
W = πd³/32
```

Следовательно, фактический диаметр участвует в:

- `EA`, `EI`, `GJ` и глобальной матрице жёсткости;
- осевых, изгибных, сдвиговых и torsion stress checks;
- локальной Euler-устойчивости;
- global eigen-buckling через фактическое напряжённое состояние;
- собственном весе;
- ветровой нагрузке на цилиндрическое ребро;
- обледенении и внешнем диаметре `d + 2tice`.

Никакого «среднего» или эквивалентного диаметра в FEM не вводится.

## Global FEM и помодульный Schur solver

Помодульный solver не предполагает одинаковую жёсткость всех октаэдров. Для каждого модуля отдельно собирается его 36-DOF матрица из девяти фактических frame-elements, после чего выполняется прежняя точная Schur-конденсация интерфейсов 18 DOF.

Поэтому смешанный профиль продолжает проверяться двумя production paths:

```text
global symmetric-band FEM
↕ all 6 DOF every node
module-by-module Schur condensation
```

Regression suite требует относительное расхождение перемещений `< 1e-8` и interface equilibrium residual `< 1e-8` и для модулей разной жёсткости.

## Нагрузки

`buildLoadCase()` строит распределённые нагрузки по свойствам каждого `member`.

Для собственного веса:

```text
mi = ρ · πdi²/4 · Li
G = Σmi · g · γg
```

Для ветра используется внешний диаметр конкретного ребра:

```text
douter,i = di + 2tice
qw,i ∝ qwind · Cd · douter,i
```

Поэтому уменьшение верхних диаметров действительно уменьшает и массу, и цилиндрическую ветровую ширину этих рёбер.

## Соединительный узел

В текущей архитектуре для всей мачты выбирается один тип физического межмодульного узла: болт, проходная гайка, длинная соединительная гайка и базовые параметры сварки.

Для смешанного профиля применяется консервативное правило:

- нетто-сечение обеих гаек проверяется относительно **максимального диаметра ребра всей мачты**;
- автоматический базовый катет сварки также выбирается по максимальному диаметру;
- силовой расчёт каждого сварного конца `N/V/T/M` использует **фактический диаметр именно этого ребра** и его площадь.

Новые ограничения момента затяжки и service-reserve сварной зоны из актуального `main` применяются совместно с этим правилом: issue #22 не отключает более свежие проверки узла.

## Ведомость и масса

`buildMaterialSummary()` и CSV группируют стержни по фактическому `member.diameterM`, поэтому смешанный профиль автоматически превращается в отдельные позиции ведомости.

Оценка производственной массы хранит:

- диаметр и массу ребра каждого модуля;
- массу каждого изготовленного модуля;
- суммарную массу профилированной мачты;
- reference-массу варианта, где все модули изготовлены из максимального диаметра;
- оценочную экономию относительно этого reference.

Метизы и сварка по-прежнему являются отдельной post-FEM оценкой и не добавляются скрыто обратно в self-weight frame-модели.

## Паспорт верификации

Старая формула массы для одинаковых рёбер:

```text
m = LΣ · πd²/4 · ρ
```

для смешанного профиля недостаточна. Независимая проверка теперь использует:

```text
m = Σ Li · πdi²/4 · ρi
G = m · g · γg
```

То есть паспорт проверяет именно сумму физических стержней модели и не подменяет профиль эквивалентным диаметром.

## Автоподбор диаметра

Функция `selectUniformDiameter()` и кнопка автоматического подбора сохраняют прежний однозначный контракт: они ищут **минимальный единый стандартный диаметр** и согласованный узел.

Если в форме включён смешанный профиль, обычный расчёт использует его точно. При запуске автоматического подбора смешанный профиль намеренно не передаётся в uniform optimizer, чтобы кандидат `Ød` не был затенён пользовательским массивом `moduleDiametersMm`.

Автоматическая многопараметрическая оптимизация распределения диаметров по высоте — отдельная задача: для неё требуется определить целевую функцию и ограничения, а не подменять её скрытой эвристикой.

## Ограничения

Issue #22 меняет диаметр, но не вводит разные классы стали, длины рёбер или отдельные комплекты метизов для каждого яруса. Сейчас общими для всей мачты остаются:

- класс арматуры и механические характеристики материала;
- геометрия правильного октаэдра и длина ребра;
- один выбранный тип межмодульного болтового узла;
- базовые параметры сварочного материала/процесса.

Как и раньше, расчёт остаётся инженерным прототипом линейной 3D Euler–Bernoulli frame-модели. Реальная конструкция требует проверки геометрической нелинейности/imperfections, фундамента, фактической жёсткости соединений, усталости и независимой инженерной валидации.

## Regression tests

`tests/mixed-module-diameters.test.js` проверяет:

- uniform fallback и расширение верхнего диаметра при height-search;
- ровно 9 рёбер с заданным диаметром в каждом physical module;
- независимый собственный вес смешанного профиля;
- global FEM ↔ module Schur equivalence при разной жёсткости модулей;
- группировку ведомости по реальным диаметрам;
- sizing общего узла по максимальному ребру;
- сварную огибающую по фактическому диаметру каждого стержня;
- восстановленный verification passport;
- сборочную массу и экономию;
- изоляцию `selectUniformDiameter()` от смешанного профиля.

Локальная команда:

```bash
npm run test:mixed-diameters
```

Полный `npm test` также включает этот suite автоматически.
