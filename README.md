# Mast Calculator

Статическое браузерное приложение для расчёта модульной телекоммуникационной мачты из сварных арматурных октаэдров. Backend не требуется: расчёт выполняется в браузере, публикация — через GitHub Pages.

Опубликованная версия:

**https://netkeep80.github.io/mast-calculator/**

- [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) — требования и расчётные допущения;
- [`docs/CALCULATION_ARCHITECTURE.md`](docs/CALCULATION_ARCHITECTURE.md) — архитектура FEM и отчётности;
- [`docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md`](docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md) — боковая нагрузка, Бофорт и solid-rod sanity-check;

- [`docs/CI_CD_REVIEW.md`](docs/CI_CD_REVIEW.md) — CI/CD.

## Прототип 0.7

Версия 0.7 сохраняет физическую постановку жёсткой 3D frame-модели 0.6, но существенно меняет численный путь и UX длительных вычислений.

Главные изменения:

1. глобальная `K` хранится как симметричная ленточная матрица и решается banded Cholesky вместо dense `O(n³)` solve;
2. геометрия элементов и факторизация `K` выполняются один раз и повторно используются для всех направлений одной модели;
3. global eigen-buckling решается matrix-free generalized Lanczos без явного построения `K^-1`;
4. эквивалентные направления ветра удаляются по точной 120° вращательной симметрии;
5. FEM и подбор диаметра вынесены в Web Worker — страница остаётся отзывчивой;
6. добавлены процент выполнения, текущий этап, elapsed time, ETA и отмена;
7. CI содержит полный 40-модульный performance regression.

На GitHub-hosted Ubuntu runner полный расчёт 40 модулей с обычными параметрами занял **860,9 мс**: 720 свободных DOF, полуширина ленты 35, 4 уникальных ветровых случая + 8 боковых.

## Практический ввод

Пользователь задаёт:

- количество модулей;
- закупочную длину арматуры 11,8 или 12 м;
- число равных частей одного прутка;
- номинальный диаметр арматуры;
- класс `А400С`, `А500С` или `А600С`;
- погодный сценарий или ручное ветровое давление;
- оборудование, лёд и дополнительные нагрузки.

Механические свойства материала берутся из каталога. Длина ребра и высота модуля вручную не вводятся.

## Геометрия правильного октаэдра

До учёта ширины реза, соединительного узла и нахлёста:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = a * sqrt(2/3)
H = Nmodules * h
```

Каждый модуль содержит:

```text
3 горизонтальных ребра
6 диагональных рёбер
= 9 рёбер
```

Все девять рёбер правильного октаэдра имеют длину `a`; это regression invariant.

## Расчётная модель

Глобальная модель — пространственная **3D Euler–Bernoulli frame FEM** с идеально жёсткими сварными узлами.

Каждый узел имеет шесть степеней свободы:

```text
[ux, uy, uz, rx, ry, rz]
```

Каждый круглый frame-element учитывает:

```text
EA
EIy
EIz
GJ
```

Solver возвращает:

```text
N
Vy, Vz
T
My, Mz
```

а также перемещения, повороты, реакции, реактивные моменты и форму общей потери устойчивости.

## Быстрый линейный solve

Топология мачты локальна: стержни соединяют узлы одного или двух соседних уровней. Поэтому `Kfree` является узкополосной.

`compileFrameSystem()` один раз выполняет:

```text
member geometry
ke + coordinate transforms
free-DOF map
assembly Kfree
banded Cholesky(Kfree)
```

После этого для очередного load case повторяются только RHS, substitution, member actions и buckling state.

Для полного расчёта одной геометрии:

```text
stiffnessFactorizationCount = 1
```

Подробности и complexity: [`docs/PERFORMANCE_AND_PROGRESS.md`](docs/PERFORMANCE_AND_PROGRESS.md).

## Общая устойчивость

После static solve по продольным усилиям строится геометрическая матрица `KG`.

Задача:

```text
(K + lambda*KG) * phi = 0
```

Версия 0.7 не обращает `K` явно. Generalized Lanczos применяет оператор:

```text
v -> solve(K, -KG*v)
```

где `solve(K, ...)` использует уже готовую ленточную Cholesky-факторизацию.

Малая reference-задача автоматически сравнивает результат Lanczos с прежним dense eigensolver.

## Нагрузки

Реализованы:

- собственный вес арматуры;
- цилиндрический слой льда;
- ветер на пространственно ориентированные рёбра;
- масса и ветер оборудования;
- дополнительные горизонтальная и вертикальная нагрузки;
- огибающая по направлениям ветра.

Собственный вес, лёд и ветер задаются distributed member loads. Для цилиндрического ребра учитывается только составляющая ветра, нормальная его оси.

## Огибающая по ветру и 120° симметрия

Идеальная трёхгранная модель периодична при повороте на 120°.

Оптимизация сначала создаёт ту же полную угловую сетку, что и раньше, затем сворачивает значения modulo 120° и удаляет только эквивалентные FEM cases.

Для шага 30°:

```text
0..330° -> 0°, 30°, 60°, 90°
12 cases -> 4 cases
```

Для шагов, не делящих 120°, сохраняются все уникальные остатки; это отдельно покрыто тестом.

## Погодные сценарии Бофорта

Dropdown содержит полную шкалу 0–12 — от штиля до урагана.

Для выбранной характерной скорости:

```text
q = rho*v²/2
rho = 1.225 кг/м³
```

Beaufort 12 начинается с 33 м/с. Также сохранён ручной режим давления.

Это сравнительные сценарии, а не замена нормативному ветровому районированию, порывам и коэффициентам высоты.

## Проверка рёбер

Для круглого сечения:

```text
A = pi*d²/4
I = pi*d⁴/64
J = pi*d⁴/32
W = pi*d³/32
```

Упругая проверка учитывает `N`, изгиб, поперечный срез и кручение. Эквивалентное напряжение — фон Мизес.

Сжатое ребро дополнительно проверяется по Эйлеру:

```text
mu = 0.5
N_E = pi²*E*I/(mu*L)²/gamma_M
```

Итоговое использование ребра — максимум stress check и local Euler check.

## Боковая нагрузка вершины

Для отдельной проверяемой характеристики создаётся чистый load case:

```text
F0 = 1 Н горизонтально в вершине
```

В нём отключены эксплуатационный ветер, лёд, собственный вес, оборудование и другие дополнительные нагрузки.

Благодаря линейности:

```text
Fmember = 1/U(1 Н)
Fglobal = lambda_cr(1 Н)*1 Н
Flim = min(Fmember, Fglobal)
```

Проверяется сектор 120° с шагом по умолчанию 15°.

UI отдельно показывает:

- первый предел боковой нагрузки;
- боковую силу общей потери устойчивости;
- механизм первого предела;
- значения в Н/кН/кгс.

Это проверочная характеристика идеальной линейной модели, а не паспортная грузоподъёмность крана.

## Solid-rod sanity-check

Для специального случая

```text
d_rib = a/2
```

решётчатая мачта сравнивается со сплошной круглой консолью той же высоты и габаритного диаметра:

```text
D = 2a/sqrt(3)
A6/Asolid = 9/8 = 1.125
```

Regression test сравнивает порядок боковой предельной силы и линейной жёсткости `K=F/delta`.

## Web Worker и индикация

`site/calculation-worker.js` выполняет:

```text
полный FEM-расчёт
wind envelope
lateral capacity
подбор стандартного диаметра
```

Main thread занимается UI, viewer и export. Поэтому даже длительный сценарий не блокирует интерфейс.

Во время вычисления отображаются:

- progress bar и процент;
- текущий этап;
- номер текущего load case;
- прошедшее время;
- ETA;
- кнопка **«Отменить расчёт»**.

Отмена завершает worker через `worker.terminate()`.

## Подбор диаметра

Стандартные диаметры проверяются последовательно в Worker. Для каждого кандидата выполняется эксплуатационная огибающая. После выбора минимального проходящего диаметра запускается полный итоговый расчёт, включая боковую проверку.

UI показывает прогресс текущего варианта и итоговый рекомендуемый диаметр.

## Бумажный расчётный проект

Кнопка **«Скачать расчётный проект»** формирует автономный HTML для передачи инженеру и печати/PDF.

Он включает:

1. исходные данные и Git SHA;
2. геометрию правильного октаэдра;
3. `A`, `I`, `J`, `W`, `G`;
4. собственный вес, лёд и ветер;
5. frame equations;
6. `N/V/T/M` определяющего ребра;
7. stress/Euler checks;
8. общую устойчивость;
9. погодный сценарий;
10. `Fmember`, `Fglobal`, `Flim`;
11. таблицы cases;
12. diagnostics и ограничения.

В бумажном проекте нет JSON. Внутренний `CalculationSnapshot v4` используется для regression/cross-check и отладки.

## Реальные соединительные узлы

Глобальная FEM-модель сознательно считает узлы идеальными и неразрушаемыми. Реальные соединения должны проверяться отдельным модулем по demand:

```text
N, Vy, Vz, T, My, Mz
```

Будущий слой должен учитывать болты/шпильки, резьбу, гайки, сварные группы, основной металл, сварочные материалы и эксцентриситеты.

## Ограничения

Пока не реализованы:

- геометрия реального соединительного узла и дополнительная физическая высота;
- ширина реза и нахлёст;
- нормативный расчёт болтов, резьбы, гаек и сварки;
- полноценные нормативные сочетания;
- геометрическая нелинейность/P-Delta;
- initial imperfections;
- пластичность и усталость;
- параметрический фундамент;
- независимые reference-results из внешнего КЭ-комплекса.

Оптимизация 0.7 меняет вычислительный алгоритм, но не отменяет эти ограничения физической модели.
