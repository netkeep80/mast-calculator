# Issue #19 — долговечность сварной зоны и корректный автоподбор крепежа

## Что исправлено

Issue #19 состоял из трёх независимых задач:

1. учитывать снижение эффективной жёсткости/работоспособности сварной зоны со временем;
2. отдельно проверить и исправить странности автоматического выбора крепежа;
3. добавить полный выбранный стандартный ряд метрической резьбы для коммерческого крепежа.

## 1. Долговечность сварной зоны

Универсального нормативного закона вида «сталь в сварном шве теряет X % модуля Юнга за год» не существует. Для сварных соединений долговечность в реальном проекте определяется как минимум сочетанием:

- остаточных сварочных напряжений и состояния HAZ;
- качества и дефектов шва;
- спектра циклических нагрузок и усталости;
- коррозии/среды;
- трещин и результатов контроля;
- фактической технологии сварки и термообработки.

Поэтому issue #19 реализован не как ложная физическая константа, а как **явный параметрический проектный reserve model**:

```text
eta_service = max(eta_min, eta0 * (1-r)^years)
```

Проектные defaults:

```text
years   = 25
eta0    = 0.97
r       = 0.0015 / год
eta_min = 0.85
```

Эти числа являются консервативными параметрами проекта и могут быть заменены при наличии данных по конкретному изделию.

### 1.1. Прочность/работоспособность сварного шва

Номинальная геометрия шва не подменяется коэффициентом. Расчёт хранит отдельно:

```text
teff,nominal = beta_f * kf
teff,service = eta_service * teff,nominal
```

И уже `teff,service` используется для:

- сопротивления металла шва на единицу длины;
- сопротивления границы сплавления;
- проектного area-reserve `Aweld/Arib`;
- требуемой эффективной и физической длины шва.

### 1.2. Жёсткость, реально участвующая в FEM

Чтобы issue #19 влиял не только на post-processing соединения, но и на перемещения/устойчивость мачты, введена отдельная модель эквивалентной податливости околошовных зон.

Каждое ребро считается состоящим из:

```text
weld-zone A + nominal middle + weld-zone B
```

Длина одной проектной околошовной зоны:

```text
Lzone = max(25 мм, 4*dbar)
```

с защитой от перекрытия зон на очень коротком элементе.

Для двух концов используется последовательное сложение упругих податливостей:

```text
Leq,compliance = Lmiddle + 2*Lzone/eta_service
eta_member = Lmember / Leq,compliance
E_FEM = E_nominal * eta_member
```

`E_nominal` сохраняется отдельно в `member.nominalYoungModulusPa`, а `member.youngModulusPa` — уже эквивалентный модуль, который реально использует frame/FEM.

За счёт этого service age влияет на:

- линейные перемещения и повороты;
- global stiffness matrix `K`;
- Euler member buckling через `E*I`;
- global eigen-buckling;
- global / Schur / independent dense cross-check одновременно, поскольку все три решателя получают одну физическую модель элементов.

Это лучше, чем просто уменьшать `E` всей арматуры: деградация локализована около сварных концов и переводится в эквивалентную податливость полного ребра.

### 1.3. Граница достоверности

Межмодульный геометрический узел в global frame всё ещё не представлен отдельными rotational/translational springs, contact elements или конечной жёсткостью резьбы. `two-end-weld-zone-series-compliance-v1` — инженерный surrogate для околошовной податливости, а не экспериментально идентифицированная moment-rotation curve конкретного соединения.

Для полноценной оценки ресурса отдельно нужны fatigue/fracture/corrosion checks и данные осмотров. Design working life должен учитывать deterioration, а fatigue welded joints обычно определяется диапазонами напряжений и числом циклов, а не одним календарным возрастом.

## 2. Почему автоподбор крепежа выглядел странно

После issue #33 auto-конфигуратор применял один и тот же пользовательский/default момент:

```text
T = 200 Н·м
```

ко всем кандидатам подряд.

Но:

```text
F0 = T/(K*d)
```

Поэтому при одинаковом `T` меньший диаметр получает непропорционально высокий преднатяг относительно своей несущей способности. Для M16 8.8 default 200 Н·м способен исчерпать расчётный растягивающий резерв ещё до внешней FEM-нагрузки. В результате auto искусственно перескакивал на более крупный болт.

### Новая политика auto

В auto-режиме программа теперь подбирает **диаметр + класс + безопасный момент затяжки**.

Максимальный преднатяг кандидата ограничен:

```text
Upreload <= 0.55
```

то есть не более 55% его расчётной растягивающей способности до добавления внешнего разделяющего усилия.

Алгоритм:

```text
запрошенный T
    ↓
T при 100% tension capacity
    ↓
0.55 * Tcapacity
    ↓
Tauto = min(Trequested, 0.55*Tcapacity)
    ↓
F0,max + Nt,external
    ↓
полный tension/shear interaction check
```

Это не означает, что M16 теперь всегда проходит: если после безопасного преднатяга внешняя нагрузка слишком велика, конфигуратор переходит к M18, M20 и далее.

### Manual остаётся manual

В ручном режиме момент **никогда не уменьшается автоматически**. Если пользователь задаёт M16 и 200 Н·м, расчёт честно показывает перегрузку.

## 3. Полный выбранный метрический ряд ISO 262:2023

Добавлен отдельный single-source каталог `metric-thread-catalog.js` для выбранных размеров коммерческого метрического крепежа ISO 262:2023.

Действующая редакция ISO 262:2023 охватывает M1…M100. В каталоге хранится coarse pitch для полного выбранного ряда:

```text
M1 M1.2 M1.4 M1.6 M1.8 M2 M2.5 M3 M3.5 M4 M5 M6 M7 M8
M10 M12 M14 M16 M18 M20 M22 M24 M27 M30 M33 M36 M39 M42 M45
M48 M52 M56 M60 M64 M68 M72 M76 M80 M85 M90 M95 M100
```

Важно разделять два понятия:

- **выбранный стандартный ряд коммерческого крепежа ISO 262** — геометрический каталог резьбы;
- **расчётный ряд конструкционных болтов СП 16** — только диаметры, для которых приложение имеет расчётные `Ab/Abn`, `Rbs/Rbt` и физическую геометрию текущего узла.

Поэтому программа не притворяется, что любая стандартная M-резьба автоматически является нормативным конструкционным болтом для текущей модели.

Полный ISO 262 coarse-thread ряд теперь также выводится в пользовательском справочнике приложения.

### Возвращены M18/M22/M27

В расчётный ряд болтов возвращены M18, M22 и M27 из таблицы Г.9. Их специальный статус сохраняется в metadata `scopeNote`, чтобы пользователь видел необходимость проверить область применения.

Также расширены обычные и длинные гайки промежуточными размерами. Это позволяет физическому конфигуратору искать проходную гайку по реальному minor diameter, а не перескакивать через отсутствующие записи каталога.

Примеры:

```text
болт M18 -> первая проходная гайка M22
болт M22 -> первая проходная гайка M27
болт M27 -> первая проходная гайка M33
```

## 4. Тесты

Добавлен `tests/issue19-durability-fasteners.test.js`.

Он отдельно фиксирует:

- полный выбранный ISO 262:2023 coarse-thread ряд M1…M100;
- наличие M18/M22/M27 в расчётном ряду;
- подбор проходной гайки по actual basic minor diameter;
- regression: auto не выбрасывает M16 только из-за универсальных 200 Н·м;
- regression: manual M16 + 200 Н·м не исправляется скрытно и проваливает bolt check;
- монотонное снижение `teff,service` с возрастом;
- рост требуемой длины шва при service degradation;
- эквивалентную series-compliance двух околошовных зон;
- фактическое уменьшение `member.youngModulusPa`, используемого FEM, при сохранении `nominalYoungModulusPa`;
- нижний предел `eta_min`.

`npm run test:issue19` запускает focused suite, а `npm test` включает его автоматически. `test:joint-strength` также включает issue #19, поэтому существующий обязательный joint-strength CI gate проверяет новую модель.

## Источники и статус допущений

- СП 16.13330.2017 — расчётные сопротивления и площади конструкционных болтов текущей модели.
- ГОСТ ISO 898-1-2014 — классы механических свойств крепежа.
- ISO 262:2023 / ISO 261 / ISO 724:2023 и ГОСТ 24705-2004 — метрическая резьба.
- NASA-STD-5020A / NASA Fastener Design Manual — инженерная связь torque/preload и необходимость учитывать реальный nut factor.
- Eurocode/JRC guidance по design working life и fatigue — основание не выдавать календарный коэффициент за универсальный закон физического старения сварного соединения.

Коэффициенты `eta0`, `r`, `eta_min`, а также проектная длина околошовной зоны `max(25 мм, 4d)` — **параметрический консервативный reserve model issue #19**, а не значения, приписанные СП, ISO или Eurocode.
