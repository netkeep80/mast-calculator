# Mast Calculator

Статическое веб-приложение для расчёта модульной телекоммуникационной мачты из сварных арматурных октаэдров. Сервер не требуется: расчёт выполняется непосредственно в браузере, приложение публикуется через GitHub Pages.

Опубликованная версия:

**https://netkeep80.github.io/mast-calculator/**

Документация:

- [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) — базовые требования и расчётные допущения;
- [`docs/CALCULATION_ARCHITECTURE.md`](docs/CALCULATION_ARCHITECTURE.md) — архитектура FEM и отчётности;
- [`docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md`](docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md) — боковая нагрузка вершины, шкала Бофорта и solid-rod sanity-check;
- [`docs/CI_CD_REVIEW.md`](docs/CI_CD_REVIEW.md) — аудит CI/CD по шаблонам link-foundation.

## Прототип 0.6

Версия 0.6 добавляет к жёсткой 3D frame-модели три проверяемых возможности:

1. расчёт чистой боковой нагрузки на вершину с отдельным выводом первого предела и глобальной потери устойчивости в Н/кН/кгс;
2. погодные сценарии по полной шкале Бофорта 0–12, включая ураган;
3. независимый sanity-check решётчатой мачты против сплошной круглой консоли того же габарита.

## Практический ввод

Пользователь задаёт:

- количество модулей;
- закупочную длину арматуры 11,8 или 12 м;
- на сколько равных частей режется один пруток;
- номинальный диаметр арматуры;
- класс `А400С`, `А500С` или `А600С`;
- погодный сценарий или пользовательское ветровое давление;
- оборудование, лёд и дополнительные нагрузки.

Механические свойства материала берутся из каталога. Длина ребра и высота модуля вручную не вводятся.

## Геометрия правильного октаэдра

До учёта ширины реза, соединительного узла и нахлёста арматуры:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = a * sqrt(2/3)
H = Nmodules * h
```

где `a` — длина каждого из девяти рёбер модуля, `h` — расстояние между треугольными гранями.

Например, для прутка 12 м, разрезанного на 16 частей:

```text
a = 750 мм
h = 612,372 мм
```

Все девять рёбер каждого модуля проверяются regression-тестами на равенство длины.

## Расчётное ядро

Глобальная модель — пространственная **3D Euler–Bernoulli frame FEM** с идеально жёсткими сварными узлами.

Каждый узел имеет шесть степеней свободы:

```text
[ux, uy, uz, rx, ry, rz]
```

Каждое круглое ребро учитывает:

```text
EA
EIy
EIz
GJ
```

Расчёт возвращает:

```text
N
Vy, Vz
T
My, Mz
```

а также перемещения, повороты, реакции и реактивные моменты.

## Нагрузки

Реализованы:

- собственный вес арматуры;
- цилиндрический слой льда;
- ветер на каждое пространственно ориентированное ребро;
- масса и ветер оборудования;
- дополнительные горизонтальная и вертикальная нагрузки;
- огибающая по направлениям ветра.

Собственный вес, лёд и ветер моделируются как распределённые нагрузки frame-element. Для цилиндрического ребра учитывается только составляющая ветра, нормальная к его оси.

## Погодные сценарии Бофорта

Dropdown содержит шкалу Бофорта от 0 до 12:

```text
0  Штиль
1  Тихий ветер
2  Лёгкий ветер
3  Слабый ветер
4  Умеренный ветер
5  Свежий ветер
6  Сильный ветер
7  Крепкий ветер
8  Очень крепкий ветер
9  Шторм
10 Сильный шторм
11 Жестокий шторм
12 Ураган
```

Характерные скорости взяты из Beaufort scale Met Office. Для выбранной скорости программа вычисляет динамическое давление:

```text
q = rho*v²/2
rho = 1.225 кг/м³
```

Ураганный сценарий начинается с `33 м/с`, что даёт около `667 Па` до применения коэффициента ветровой нагрузки.

Также сохранён режим ручного ввода ветрового давления.

Погодные пресеты предназначены для наглядного сравнения сценариев и **не заменяют** нормативное ветровое районирование, коэффициенты высоты, пульсацию и сочетания по СП 20.

## Проверка рёбер

Для круглого сечения:

```text
A = pi*d²/4
I = pi*d⁴/64
J = pi*d⁴/32
W = pi*d³/32
```

Упругая проверка учитывает осевое усилие, изгиб, поперечный срез и кручение. Эквивалентное напряжение рассчитывается по фон Мизесу.

Сжатое ребро дополнительно проверяется по Эйлеру. Для текущей идеализации абсолютно жёстких концов:

```text
mu = 0.5
N_E = pi² E I / (mu L)² / gamma_M
```

Итоговый коэффициент использования ребра — максимум проверки напряжений и локальной устойчивости.

## Общая устойчивость

После статического frame-расчёта собирается геометрическая матрица `K_G` и решается линейная собственная задача:

```text
(K + lambda K_G) phi = 0
```

Приложение показывает минимальный критический множитель и первую форму общей потери устойчивости.

## Максимальная боковая нагрузка вершины

Для отдельной проверяемой характеристики программа создаёт специальный случай:

```text
F0 = 1 Н горизонтально в вершине
```

Сила поровну распределяется между тремя верхними узлами. В этом **испытательном** случае отключены ветер, лёд, собственный вес, оборудование и другие нагрузки.

Благодаря линейности:

```text
Fmember = 1 / U(1 Н)
Fglobal = lambda_cr(1 Н) * 1 Н
Flim = min(Fmember, Fglobal)
```

Программа перебирает направления в секторе 120° и выбирает худшее. По умолчанию шаг 15°.

В UI отдельно показываются:

```text
Flim     — первый предел боковой нагрузки
Fglobal  — боковая сила линейной общей потери устойчивости
mode     — механизм первого предела
```

Значения выводятся в Н/кН и `кгс`. Килограмм-сила используется сознательно, чтобы не смешивать массу и силу.

Если `Flim < Fglobal`, материал или локальное ребро достигают своего предела раньше общей потери устойчивости; это важнее для реальной конструкции, чем скрывать более ранний механизм разрушения.

Значение в кгс удобно для натурной проверки тарированным усилием, но оно **не является паспортной грузоподъёмностью крана**. Реальная конструкция имеет собственный вес, несовершенства и нелинейность, которых нет в этом чистом нормированном тесте.

## Solid-rod sanity-check

Для специального предельного случая

```text
d_rib = a/2
```

мачта автоматически сравнивается в тестах со сплошной круглой консолью:

```text
высота = H мачты
диаметр = D = 2a/sqrt(3)
материал = тот же
```

У шести рёбер диаметра `a/2` суммарная площадь стали относительно сплошного стержня диаметра `D` равна:

```text
A6 / Asolid = 9/8 = 1.125
```

То есть количество стали отличается всего на 12,5%, поэтому сравнение разумно как проверка порядка величин.

Regression test сравнивает:

- предельную боковую силу;
- боковую линейную жёсткость `K=F/delta`.

Тест не требует искусственного равенства двух разных конструкций, но падает, если расчёты расходятся на порядок.

Подробный вывод: [`docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md`](docs/LATERAL_CAPACITY_WEATHER_VALIDATION.md).

## Реальные соединительные узлы

Глобальная FEM-модель сознательно считает узлы идеальными и неразрушаемыми. Реальные соединения должны проверяться отдельным модулем по demand:

```text
N, Vy, Vz, T, My, Mz
```

В будущий расчёт узлов входят болт/шпилька, резьба, гайка, сварная группа, основной металл, сварочные материалы и эксцентриситеты.

## Бумажный расчётный проект

Кнопка **«Скачать расчётный проект»** формирует автономный HTML для передачи инженеру и печати/PDF.

Документ пошагово показывает:

1. исходные данные и Git SHA;
2. геометрию правильного октаэдра;
3. `A`, `I`, `J`, `W`, `G`;
4. собственный вес, лёд и ветер;
5. устройство 3D frame-element и `K u = F`;
6. `N/V/T/M` определяющего ребра;
7. напряжения и локальный Эйлер;
8. общую устойчивость;
9. выбранный погодный сценарий и `q=rho*v²/2`;
10. вывод боковой нагрузки `Fmember`, `Fglobal`, `Flim` с численными подстановками;
11. таблицы ветровых и боковых направлений;
12. численные невязки и ограничения.

В бумажном проекте нет JSON. Внутренний `CalculationSnapshot v4` используется только для regression/cross-check и отладки.

## Верификация

Автоматические тесты включают:

- `delta = FL/(EA)`;
- `delta = PL³/(3EI)` и `theta = PL²/(2EI)`;
- fixed-fixed beam: `qL/2` и `qL²/12`;
- аналитическую боковую прочность круглой консоли по полной используемой solver формуле `sigma_eq = sqrt((PL/W)^2 + 3(4P/3A)^2)`;
- равновесие сил и моментов;
- поворотную инвариантность;
- геометрию правильного октаэдра;
- полный Beaufort 0–12 и формулу динамического давления;
- монотонность погодных давлений;
- solid-rod sanity-check по прочности и жёсткости;
- UI/report contracts;
- policy тесты GitHub workflows.

До признания инструмента окончательным требуется cross-check с независимым КЭ-комплексом на эталонных моделях.

## CI/CD

PR CI выполняет:

```text
Syntax, policy and maintainability
Secrets scan
Tests — Ubuntu
Tests — macOS
Tests — Windows
Static site smoke test
```

Используются современные official GitHub Actions, явные timeout, least-privilege permissions, fresh-merge simulation, secretlint, file-size guard и cross-platform matrix.

GitHub Pages публикуется отдельным serialized writer job. SHA опубликованного коммита записывается в `build-info.json` и попадает в бумажный расчётный проект.

## Ограничения 0.6

Пока не реализованы:

- реальная геометрия соединительных узлов и нахлёст арматуры;
- нормативный расчёт болтов, резьбы, гаек и сварных швов;
- полноценные нормативные сочетания нагрузок;
- геометрическая нелинейность и начальные несовершенства;
- пластичность и усталость;
- параметрический фундамент;
- динамика рывка груза;
- независимые reference-results из внешнего КЭ-комплекса.

## Локальный запуск

```bash
python3 -m http.server 8080 --directory site
```

Открыть `http://localhost:8080`.

Проверки:

```bash
npm test
npm run check
node scripts/check-file-line-limits.mjs
```

У проекта нет runtime npm-зависимостей; Node.js используется как test runner и для CI utility scripts.

## Единицы

Внутри расчётного ядра используются SI: метры, ньютоны, паскали, радианы и килограммы. UI и бумажный проект преобразуют значения в удобные инженерные единицы, включая кгс только как единицу силы для натурной боковой проверки.
