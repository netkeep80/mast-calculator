# Требования к Mast Calculator

Статус: рабочая спецификация для следующих версий приложения.

## 1. Цель

Приложение должно оставаться простым статическим веб-приложением для GitHub Pages, но расчётное ядро и отчётность должны быть пригодны для инженерной проверки и независимого воспроизведения.

Основной пользовательский сценарий — изготовитель/сборщик мачты. Поэтому в обычном интерфейсе вводятся прежде всего реальные закупочные и технологические параметры, а не абстрактные механические константы.

## 2. Практический ввод исходных данных

### 2.1. Арматура

В обычном режиме задаются:

- закупочная длина прутка — выбор из фиксированного списка (на первом этапе 11,8 м и 12 м);
- количество равных частей, на которые режется один пруток — выпадающий список;
- теоретическая длина одной заготовки — только для чтения;
- номинальный диаметр арматуры — выпадающий список стандартных/практически применяемых типоразмеров;
- класс арматуры — выпадающий список материалов с гарантированной свариваемостью;
- количество модулей;
- фактическая высота одного модуля.

Параметры `E`, предел текучести и плотность пользователь в обычном режиме не вводит: они берутся из каталога материала.

### 2.2. Текущая связь раскроя и расчётной геометрии

На этапе 0.4 применяется временное правило:

```text
длина_заготовки = закупочная_длина / количество_частей
сторона_горизонтального_треугольника = длина_заготовки
```

Высота модуля задаётся отдельно по фактическому изготовленному размеру.

Это временное приближение. В окончательной модели необходимо различать:

- длину физической заготовки;
- длину между расчётными осями узлов;
- припуск/нахлёст на сварку;
- геометрию гайки/болта;
- ширину реза и технологическую подрезку.

Нельзя незаметно приравнивать длину заготовки к расчётной длине элемента после того, как геометрия реального узла будет формализована.

### 2.3. Раскрой

Отдельный производственный модуль должен учитывать:

- закупочную длину;
- количество деталей;
- ширину реза;
- торцевую подрезку;
- допустимый технологический остаток;
- повторное использование остатка;
- суммарное количество исходных прутков;
- массу и стоимость отходов.

## 3. Разделение глобального расчёта и расчёта узлов

### 3.1. Глобальная модель арматурного каркаса

Глобальный расчёт должен отвечать только на вопрос, выдерживает ли сам арматурный каркас заданные нагрузки, если соединения в узлах считать идеальными и неразрушаемыми.

Реальная прочность болтов, резьбы, гаек и сварных швов не должна искусственно смешиваться с глобальной моделью.

### 3.2. Важное следствие для КЭ-модели

Требование «сварено намертво» означает передачу не только продольных сил, но и изгибающих моментов/кручения. Поэтому целевая модель не должна оставаться чистой шарнирной фермой с тремя поступательными степенями свободы на узел.

Целевая модель — пространственная frame-модель:

- 6 степеней свободы на узел: `ux, uy, uz, rx, ry, rz`;
- стержень круглого сечения как 3D beam/frame element;
- осевая жёсткость `EA`;
- изгибные жёсткости `EIy`, `EIz`;
- крутильная жёсткость `GJ`;
- жёсткое соединение элементов в идеальном расчётном узле.

Текущий линейный 3D truss solver остаётся переходной моделью и должен быть заменён до того, как результаты будут считаться окончательными.

### 3.3. Интерфейс передачи усилий в расчёт узла

После каждого глобального расчётного случая для каждого физического узла должен формироваться demand envelope. Минимальный набор:

```text
N   — продольная сила;
Vy  — поперечная сила в локальной оси y;
Vz  — поперечная сила в локальной оси z;
T   — крутящий момент;
My  — изгибающий момент относительно y;
Mz  — изгибающий момент относительно z;
loadCaseId / направление ветра.
```

Расчёт узла получает только эту нагрузочную информацию и геометрию соединения.

## 4. Отдельный расчёт реального узла

### 4.1. Входные данные

Для узла должны задаваться/подбираться:

- тип узла;
- номинальная резьба (например M20/M22/M24/M30);
- шаг резьбы;
- класс прочности болта/шпильки;
- материал гайки/соединительной гайки;
- длина резьбового зацепления;
- число плоскостей среза;
- расположение арматуры относительно оси болта;
- тип сварочного соединения;
- количество сварных швов;
- длина каждого шва;
- катет/эффективная толщина;
- способ сварки;
- тип/марка и диаметр электрода или сварочной проволоки;
- материал свариваемых деталей.

### 4.2. Проверки

Отдельный модуль узлов должен проверять как минимум:

- болт/шпильку на растяжение;
- болт/шпильку на срез;
- совместное действие растяжения и среза;
- срыв наружной и внутренней резьбы;
- достаточность длины зацепления;
- смятие контактных поверхностей, где это применимо;
- прочность гайки/соединительной гайки;
- сварную группу по металлу шва;
- сварную группу по границе сплавления;
- основной металл около шва;
- действие эксцентриситета и момента на сварную группу.

Результат узла:

```text
PASS / FAIL
коэффициент использования
определяющий механизм разрушения
допустимая нагрузка
фактическая нагрузка
спецификация крепежа и сварки
```

Главное правило: **несущая способность узла должна быть не ниже спроса, полученного от глобального расчёта каркаса**.

## 5. Каталог материалов

### 5.1. Арматура

На первом этапе каталог содержит классы `А400С`, `А500С`, `А600С` по ГОСТ 34028-2016, поскольку для сварной конструкции нужна гарантированная свариваемость.

Для каждого класса каталог хранит:

- нормативный источник;
- минимальный предел текучести;
- минимальное временное сопротивление;
- модуль упругости, используемый расчётной моделью;
- плотность;
- признак гарантированной свариваемости.

Каталожные величины не должны дублироваться в UI или в нескольких расчётных модулях.

### 5.2. Болты и резьба

Для расчёта крепежа следует опираться на действующие нормативные данные по механическим свойствам болтов/шпилек и геометрии метрической резьбы. Табличные значения должны храниться в каталоге с указанием источника и редакции.

### 5.3. Сварка

Каталог сварочных материалов должен связывать:

- процесс сварки;
- тип сварного соединения;
- материал деталей;
- расчётную температуру;
- тип/марку электрода или проволоки;
- механические характеристики металла шва.

Выбор электрода/проволоки нельзя определять только по диаметру арматуры.

## 6. Верификация расчётов

### 6.1. Расчётная записка

После расчёта приложение должно формировать автономный документ, который можно передать инженеру-конструктору для независимой проверки.

Минимальное содержание:

1. версия программы и идентификатор метода расчёта;
2. Git commit опубликованной версии;
3. дата/время расчёта;
4. все пользовательские исходные данные;
5. все автоматически полученные параметры материала;
6. расчётная геометрия — координаты узлов, связи, сечения, закрепления;
7. нагрузки и расчётные случаи;
8. описание расчётной модели и допущений;
9. основные формулы/методы;
10. сводные результаты;
11. усилия/напряжения по элементам;
12. результаты устойчивости;
13. demand envelope для узлов;
14. результаты проверок узлов;
15. численная диагностика и невязки;
16. список предупреждений и ещё не реализованных нормативных проверок;
17. полный машинно-читаемый снимок расчёта.

### 6.2. Один источник истины

Документ **не должен выполнять отдельный повторный расчёт**.

После завершения solver создаёт канонический `CalculationSnapshot`. Из него без изменения чисел строятся:

```text
экран результатов
CSV
JSON
HTML/PDF расчётная записка
сравнение с эталонными результатами
```

Таким образом инженер проверяет именно те данные, которые использовались приложением внутри.

### 6.3. Машинный снимок

`CalculationSnapshot` должен содержать без сокращения:

- входные и производные параметры;
- координаты всех узлов;
- список всех элементов;
- закрепления;
- узловые нагрузки по каждому случаю;
- перемещения;
- реакции;
- усилия и проверки каждого элемента;
- собственную форму/множитель устойчивости;
- численные невязки;
- версии схемы данных и метода расчёта;
- Git SHA.

Человекочитаемая расчётная записка должна содержать этот JSON в приложении или поставляться вместе с ним.

### 6.4. Независимая проверка

До признания расчётного ядра пригодным для практического проектирования необходимо иметь набор моделей, рассчитанных также независимым КЭ-комплексом.

Минимальный набор эталонов:

- одиночный стержень на растяжение;
- балка/консоль для проверки frame element;
- простая пространственная рама;
- один модуль;
- два модуля с зеркальной геометрией;
- полная мачта;
- несимметричный ветровой случай;
- собственная форма потери устойчивости.

Допуски сравнения задаются отдельно для перемещений, реакций, усилий и собственных значений.

## 7. Нормативная база, которую необходимо учитывать

На момент составления требований:

- ГОСТ 34028-2016 — арматурный прокат; сортамент, механические свойства, дополнительные требования по свариваемости;
- ГОСТ ISO 898-1-2014 — механические свойства болтов, винтов и шпилек установленных классов прочности;
- ГОСТ 24705-2004 — основные размеры метрической резьбы;
- СП 16.13330.2017 — расчёт и проектирование стальных конструкций, в том числе сварных соединений;
- ГОСТ 5264-80 — основные типы и конструктивные размеры соединений ручной дуговой сварки;
- ГОСТ 9467-75 — типы покрытых электродов для конструкционных сталей;
- СП 20.13330.2016 — нагрузки, воздействия и их сочетания;
- ГОСТ 27751-2014 — общие принципы надёжности строительных конструкций и оснований.

Версии/изменения нормативов должны фиксироваться в расчётной записке. Наличие ссылки на норматив не означает, что текущая версия программы уже реализует все его проверки.

## 8. Порядок реализации

1. Практический ввод закупочной длины, раскроя, диаметра и класса арматуры.
2. Канонический полный `CalculationSnapshot` и автономная расчётная записка.
3. Замена 3D truss solver на 3D frame solver с жёсткими идеальными узлами.
4. Формирование demand envelope `N/V/T/M` для каждого физического узла.
5. Каталог крепежа, резьбы и сварочных материалов.
6. Проверки реальных узлов.
7. Автоматические сочетания нагрузок по выбранной нормативной схеме.
8. Геометрическая нелинейность и начальные несовершенства.
9. Оптимизация стоимости, массы и раскроя.
10. Набор независимых верификационных моделей.
