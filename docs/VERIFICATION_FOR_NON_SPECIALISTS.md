# Как неспециалисту проверять расчёт Mast Calculator

Статус: подход прототипа 0.9 для issue #12.

## 1. Проблема

Для пространственной frame-модели недостаточно показать пользователю матрицу `K`, сотни перемещений и надпись «тесты пройдены». Неспециалист всё равно не сможет вручную проверить тысячи арифметических операций, а большой объём вывода сам по себе ничего не доказывает.

Поэтому Mast Calculator использует не бинарный значок «верно/неверно», а **цепочку независимых свидетельств**. Каждый следующий уровень отвечает на другой класс возможных ошибок.

Главное правило:

> зелёная внутренняя верификация означает, что реализованная математическая модель внутренне согласована с перечисленными проверками; она не означает, что реальная мачта автоматически доказана безопасной.

## 2. Шесть уровней доверия

### Уровень 1. То, что можно пересчитать на обычном калькуляторе

Пользователь может независимо проверить исходные величины, которые затем входят в FEM.

#### 2.1. Длина ребра

```text
a = L0 / n
```

где `L0` — закупочная длина прутка, `n` — число равных частей.

Пример:

```text
L0 = 12000 мм
n = 16
a = 12000/16 = 750 мм
```

#### 2.2. Высота правильного октаэдра

```text
h = a*sqrt(2/3)
```

Для `a = 750 мм`:

```text
h ≈ 612.372 мм
```

#### 2.3. Полная высота

```text
H = N*h
```

Паспорт проверяет не только отображаемое значение, но и фактическую разность максимальной и минимальной `z`-координаты узлов FEM.

#### 2.4. Число рёбер

Один модуль имеет:

```text
3 горизонтальных + 6 диагональных = 9 рёбер
```

При замкнутом верхнем треугольнике дополнительно присутствуют 3 верхних ребра:

```text
Nmembers = 9*Nmodules + 3
```

#### 2.5. Равенство длин рёбер

Для каждого FEM-member программа вычисляет расстояние между его двумя узлами и сравнивает с `a`.

Это отдельная проверка топологии: правильная формула `h` ещё не гарантирует, что все связи между узлами построены правильно.

#### 2.6. Масса каркаса

Для одинаковых круглых рёбер:

```text
A = pi*d²/4
Lsum = Nmembers*a
m = Lsum*A*rho
```

где `rho` — плотность стали.

Эта проверка особенно полезна для обнаружения ошибок миллиметры/метры и неправильного числа рёбер.

#### 2.7. Собственный вес

```text
G = m*g*gamma_g
g = 9.80665 м/с²
```

#### 2.8. Ветровое давление из скорости

```text
q = rho_air*v²/2
rho_air = 1.225 кг/м³
```

Эти шаги намеренно просты: их можно повторить в телефоне, Excel или на инженерном калькуляторе без знания метода конечных элементов.

## 3. Уровень 2. Законы равновесия и численная невязка

Даже если пользователь не умеет собирать frame-element, готовое решение обязано удовлетворять базовым законам механики и собственной системе уравнений.

### 3.1. Баланс сил

Для определяющего случая:

```text
sum(R) + sum(Fexternal) = 0
```

Программа отдельно вычисляет нормированную ошибку замыкания.

Это понятная физическая проверка: если на конструкцию действует 1000 Н вниз, опоры в сумме должны дать примерно 1000 Н вверх с учётом всех остальных компонент нагрузки.

### 3.2. Баланс моментов

Относительно общего начала координат:

```text
sum(r x F) + sum(Mexternal) + sum(Mreaction) = 0
```

Это сложнее пересчитать вручную, но смысл тот же: конструкция не должна создавать момент «из ничего».

### 3.3. Невязка линейной системы

После вычисления `u` программа заново проверяет:

```text
r = K*u - F
```

и контролирует относительную норму:

```text
||r||/||F|| < 1e-8
```

Это не проверяет правильность самой физической модели, но подтверждает, что численный solver действительно решил ту систему, которую программа собрала.

### 3.4. Равновесие свободных DOF

После восстановления усилий элементов свободный узел не должен иметь необъяснимого остаточного усилия. Порог прототипа:

```text
maximum free DOF residual < 1e-8
```

### 3.5. Невязка общей устойчивости

Для найденных `lambda` и `phi` проверяется исходное уравнение:

```text
(K + lambda*KG)*phi = 0
```

а не только внутренний критерий остановки Lanczos.

Порог:

```text
buckling residual < 1e-5
```

## 4. Уровень 3. Задачи с ответом в одну формулу

Это ключевой мост между «я не понимаю FEM» и «я могу проверить программу».

Mast Calculator при каждом полном расчёте запускает маленькие эталонные задачи **тем же `analyzeFrame()`**, которым считается мачта.

### 4.1. Растяжение одного стержня

Консольный стержень растягивается осевой силой `F`.

Из сопромата:

```text
delta = F*L/(E*A)
A = pi*d²/4
```

Программа решает эту задачу своим 12×12 frame-element и сравнивает перемещение с формулой.

### 4.2. Прогиб консоли

Для поперечной силы `P` на конце:

```text
I = pi*d⁴/64
delta = P*L³/(3*E*I)
```

### 4.3. Поворот конца консоли

Для той же задачи:

```text
theta = P*L²/(2*E*I)
```

Совпадение одновременно прогиба и поворота проверяет разные строки/столбцы изгибной части frame-element. Вероятность случайно получить обе величины правильно при серьёзной ошибке ниже, чем при одной контрольной цифре.

## 5. Уровень 4. Другой алгоритм считает ту же математическую задачу

Один и тот же код может сам себя последовательно считать неправильно. Поэтому для численного слоя используются отдельные reference-алгоритмы.

### 5.1. Dense Gaussian vs banded Cholesky

Рабочий solver использует оптимизированную симметричную ленточную Cholesky-факторизацию.

В verification self-test небольшая SPD-матрица решается двумя независимыми путями:

```text
A*x=b -> dense Gaussian solver
A*x=b -> symmetric band Cholesky
```

Сравниваются:

```text
max |x_dense - x_band|
relative residual
```

Это не доказательство механической модели, зато хорошо ловит ошибки оптимизированного линейного solver.

### 5.2. Eigen-buckling с заранее известным ответом

Используется задача:

```text
K  = diag(2, 8)
KG = diag(-1, -2)
```

Уравнения независимы:

```text
2 - lambda = 0     -> lambda = 2
8 - 2*lambda = 0   -> lambda = 4
```

Первый критический множитель обязан быть:

```text
lambda_cr = 2
```

Его независимо находят dense reference и рабочий banded/Lanczos путь.

## 6. Что означают уровни 1–4

Если все внутренние уровни зелёные, подтверждено следующее:

- геометрические и массовые исходные величины согласуются с простыми формулами;
- готовые FEM-решения замыкают силы и моменты;
- численный solver имеет малую невязку;
- frame-element воспроизводит классические аналитические задачи;
- быстрые линейный и eigen-solvers согласуются с отдельными reference-алгоритмами на малых задачах.

При этом **ещё не подтверждено**:

- что принятая идеализация реального узла соответствует железу;
- что все реальные нагрузки включены;
- что линейная модель достаточна возле предельного состояния;
- что нет общей одинаковой ошибки в постановке сложной полной мачты;
- что свойства фактической арматуры и сварки соответствуют введённым данным.

Именно поэтому паспорт не превращает следующие уровни в зелёные автоматически.

## 7. Уровень 5. Независимый КЭ-комплекс

Для инженерной верификации требуется построить ту же модель в стороннем FEM-пакете.

Сравнение имеет смысл только при одинаковой постановке. Нужно зафиксировать:

```text
геометрию и координаты узлов
топологию members
E и nu
A, I, J
жёсткие соединения без releases
полную заделку основания
единицы
каждый load vector
распределённые нагрузки
коэффициенты нагрузок
```

Для нескольких эталонных моделей следует сравнить:

```text
узловые перемещения ux,uy,uz
повороты rx,ry,rz
опорные реакции и моменты
N, Vy, Vz, T, My, Mz каждого member
критический lambda_cr
форму первого buckling mode
```

Рекомендуемая последовательность reference-моделей:

1. один beam;
2. простая пространственная рама;
3. один октаэдр;
4. два зеркально чередующихся модуля;
5. полная мачта без ветра;
6. полная мачта с несимметричным ветром;
7. отдельный eigen-buckling case.

В репозитории должны храниться или однозначно идентифицироваться:

- название и версия внешнего FEM-пакета;
- файл модели или инструкция его построения;
- таблица входных параметров;
- исходные результаты;
- выбранные допуски сравнения;
- дата и Git SHA Mast Calculator.

До появления такого набора UI честно показывает **«НЕ ПРОВЕРЕНО»**.

## 8. Инженерная рецензия

Даже совпадение двух FEM-программ может означать, что обе получили одну и ту же неверную постановку от человека.

Поэтому отдельный пункт уровня 5 — рецензия инженером-конструктором:

- соответствуют ли нагрузки реальной задаче;
- достаточны ли коэффициенты и сочетания;
- допустима ли идеализация жёстких соединений;
- нужны ли P-Delta, initial imperfections или нелинейность;
- корректно ли интерпретируется eigen-buckling;
- правильно ли назначены граничные условия фундамента;
- какие нормативные проверки ещё обязательны.

Рецензенту следует передавать **сгенерированный расчётный проект**, потому что он содержит те же численные результаты, которые использовал UI.

## 9. Уровень 6. Физическое подтверждение

Натурный тест принципиально полезен: он включает реальные отклонения геометрии, сварку, свойства материала, люфты и жёсткость узлов — то, чего нет в идеальной FEM-модели.

Для обычной проверки предпочтительнее недеструктивный путь:

1. точно измерить геометрию образца;
2. приложить несколько заранее выбранных безопасных уровней нагрузки;
3. измерить перемещения в одних и тех же точках;
4. снять нагрузку и проверить остаточную деформацию;
5. сравнить кривую `F -> delta` с расчётной в линейном диапазоне.

Испытание до фактической потери устойчивости — уже отдельная испытательная работа. Для него нельзя использовать UI-число как инструкцию «навесить такой груз»: требуется специально разработанная безопасная схема нагружения, дистанционное управление и отсутствие людей в зоне возможного падения/разрушения.

## 10. Как читать паспорт в интерфейсе

Статусы имеют намеренно различный смысл:

```text
✓ ПРОЙДЕНО
  автоматическая проверка была выполнена и уложилась в заданный допуск

✗ ОШИБКА
  внутренняя проверка не прошла; расчёт нельзя принимать до выяснения причины

○ НЕ ПРОВЕРЕНО
  программа не имеет независимого доказательства этого уровня
```

Серый статус — не сбой и не предупреждение CI. Это сознательная граница знания программы.

## 11. Правило принятия результата

Для прототипа фиксируется простой порядок:

1. **Любой `FAIL` уровня 1–4 блокирует доверие к расчёту.**
2. Все уровни 1–4 `PASS` означают только внутреннюю верификацию реализации.
3. Перед использованием как окончательного инженерного расчёта требуется закрыть уровень 5 независимым FEM cross-check и инженерной рецензией.
4. Для ответственной конструкции уровень 6 даёт дополнительную валидацию уже реального изделия.

В терминах software verification/validation это различие принципиально:

```text
verification: правильно ли мы решили сформулированную математическую задачу?
validation: достаточно ли эта задача описывает реальную конструкцию?
```

Mast Calculator 0.9 существенно усиливает первую часть и **явно не притворяется**, что автоматически выполнил вторую.

## 12. Где сохраняются доказательства

Один и тот же verification object используется тремя представлениями:

```text
calculateCompleteMast()
        |
        +-- UI: уровни и раскрываемые шаги
        +-- бумажный расчётный проект: формулы, подстановки и инструкции
        +-- CalculationSnapshot v6: машинно-воспроизводимые статусы и значения
```

Renderer отчёта не пересчитывает FEM и не имеет отдельной версии формул результата.

## 13. CI regression

`tests/verification.test.js` проверяет не только «зелёный путь», но и отрицательный сценарий: тест намеренно изменяет рассчитанную массу каркаса на 5%, повторно строит паспорт и требует, чтобы проверка `steel-mass` стала `FAIL`.

40-модульный performance/regression case также требует:

```text
verification.failed = 0
levels 1..4 = PASS
verificationInternalCheckCount согласован с паспортом
```

Таким образом CI контролирует сам механизм контроля, а не только наличие текста «верификация» в интерфейсе.
