# Mast Calculator

Статическое браузерное приложение для расчёта модульной мачты из сварных арматурных октаэдров. Backend не требуется: расчёт выполняется в браузере, публикация — через GitHub Pages.

Опубликованная версия: **https://netkeep80.github.io/mast-calculator/**

## Прототип 0.9

Версия 0.9 добавляет **многоуровневый паспорт верификации**. Его цель — не показывать неспециалисту тысячи чисел FEM и просить им поверить, а дать цепочку проверок с разной степенью независимости.

Текущие возможности:

1. правильная геометрия октаэдров из закупочной длины арматуры;
2. жёсткая 3D Euler–Bernoulli frame FEM, 6 DOF/узел;
3. symmetric band Cholesky и одна факторизация `K` для load cases одной геометрии;
4. matrix-free generalized Lanczos для global eigen-buckling;
5. ветровая огибающая и погодные сценарии Бофорта 0–12;
6. отдельная проверочная боковая нагрузка вершины;
7. отдельная gravity-only максимальная масса на вершине с учётом собственного веса;
8. Web Worker, progress, elapsed time, ETA и отмена;
9. printable расчётный проект с формулами и численными подстановками;
10. verification passport: ручные формулы → равновесие → аналитические эталоны → reference-solvers → внешняя проверка → физический эксперимент;
11. regression tests на Linux/macOS/Windows, включая 40-модульную модель.

## Практический ввод и геометрия

Пользователь задаёт закупочную длину прутка, число частей раскроя, стандартный диаметр и класс арматуры. До учёта kerf/trim/joint overlap:

```text
a = Lstock / nparts
R = a / sqrt(3)
h = a * sqrt(2/3)
H = Nmodules * h
```

Один правильный октаэдр содержит 3 горизонтальных и 6 диагональных рёбер. Все девять рёбер имеют длину `a`; это regression invariant. Длина ребра и высота модуля не вводятся вручную.

## 3D frame FEM

Каждый узел имеет:

```text
[ux, uy, uz, rx, ry, rz]
```

Круглый Euler–Bernoulli frame-element учитывает:

```text
EA
EIy
EIz
GJ
```

Solver восстанавливает `N`, `Vy/Vz`, `T`, `My/Mz`, перемещения, повороты, реакции и реактивные моменты. Нижние три узла пока полностью заделаны; реальный фундамент — отдельный будущий слой.

Для круглого сечения:

```text
A = pi*d²/4
I = pi*d⁴/64
J = pi*d⁴/32
W = pi*d³/32
```

Проверка ребра объединяет осевое напряжение, изгиб, поперечный срез и кручение по фон Мизесу. Сжатое ребро дополнительно проверяется по Эйлеру с `mu=0.5` для текущей идеализации идеально жёстких концов.

## Нагрузки и погода

Эксплуатационные cases поддерживают собственный вес, лёд, ветер на пространственно ориентированные рёбра, массу и парусность оборудования, дополнительные горизонтальную/вертикальную силы и огибающую по направлениям ветра.

Погодные presets покрывают Бофорт 0–12. Для скорости:

```text
q = rho_air*v²/2
rho_air = 1.225 kg/m³
```

Presets предназначены для сравнения сценариев и не заменяют нормативный wind design по СП 20.

## Общая устойчивость

После статического frame-расчёта решается:

```text
(K + lambda*KG)*phi = 0
```

Рабочий путь применяет оператор matrix-free:

```text
v -> -KG*v -> solve(K, ...) -> K^-1(-KG)v
```

Lanczos подтверждает найденную пару фактической невязкой исходной generalized eigen-задачи.

## Compile once, solve many

`compileFrameSystem()` один раз вычисляет геометрию элементов, free-DOF map, banded `K` и `Cholesky(K)`. Эксплуатационные, боковые и статические специальные cases используют ту же факторизацию.

Для текущей 40-модульной модели:

```text
free DOF = 720
half-bandwidth = 35
stiffnessFactorizationCount = 1
```

## Боковая нагрузка вершины

Отдельный проверочный case прикладывает чистую горизонтальную силу `1 N` к верхней грани, отключая ветер, лёд, собственный вес и оборудование.

Из линейности:

```text
Fmember = 1/U(1 N)
Fglobal = lambda_cr(1 N)*1 N
Flim = min(Fmember, Fglobal)
```

Проверяется сектор 120°; UI отдельно показывает первый предел, global buckling limit и механизм в Н/кН/кгс. Это характеристика идеальной модели, а не паспортная грузоподъёмность крана.

## Максимальная статическая масса на вершине

Gravity-only сценарий оставляет собственный вес мачты и прикладывает искомую суммарную массу вертикально вниз. Для каждого пробного `m` проверяются:

```text
U_member(m) <= 1
lambda_cr(m) >= 1
```

Финальный предел уточняется двоичным поиском с собственным весом. UI показывает общую допустимую массу, остаток после уже заданного оборудования и эквивалентный объём воды при `rho_water = 1000 kg/m³`.

Подробности: [`docs/STATIC_PAYLOAD_CAPACITY.md`](docs/STATIC_PAYLOAD_CAPACITY.md).

## Паспорт верификации для неспециалиста

`calculateCompleteMast()` строит `result.verification`. Паспорт намеренно делит доверие к расчёту на шесть уровней.

### Уровень 1 — обычный калькулятор

Автоматически и с численной подстановкой проверяются:

```text
a = L0/n
h = a*sqrt(2/3)
H = N*h
число и фактические длины рёбер
m = Lsum*pi*d²/4*rho
G = m*g*gamma_g
q = rho_air*v²/2
```

UI и бумажный проект объясняют, как повторить каждый шаг самому.

### Уровень 2 — законы равновесия

Контролируются:

```text
sum(R) + sum(F) = 0
sum(M) = 0
||K*u-F||/||F|| < 1e-8
free-DOF equilibrium < 1e-8
buckling residual < 1e-5
```

### Уровень 3 — задачи с известным ответом

Тем же frame solver автоматически решаются маленькие задачи:

```text
delta_axial = F*L/(E*A)
delta_cantilever = P*L³/(3*E*I)
theta_cantilever = P*L²/(2*E*I)
```

Программа показывает ожидаемое и фактическое значение.

### Уровень 4 — другой численный алгоритм

Оптимизированная banded Cholesky сравнивается с отдельным dense Gaussian solver. Eigen-buckling dense и banded/Lanczos сравниваются на диагональной задаче с заранее известным `lambda_cr = 2`.

### Уровни 5–6 — программа не может проверить сама себя

Они намеренно имеют статус `НЕ ПРОВЕРЕНО`, пока нет:

- модели той же конструкции в независимом КЭ-комплексе;
- инженерной рецензии расчётного проекта;
- физического подтверждения контрольного образца.

Это принципиальная часть подхода: **зелёные внутренние тесты не превращаются в заявление, что реальная конструкция доказанно безопасна**.

Подробный пошаговый подход и протокол внешней проверки: [`docs/VERIFICATION_FOR_NON_SPECIALISTS.md`](docs/VERIFICATION_FOR_NON_SPECIALISTS.md).

## Защита самого паспорта от фиктивного «зелёного» статуса

CI содержит отрицательный regression: тест намеренно искажает рассчитанную массу каркаса на 5%, повторно строит паспорт и требует, чтобы проверка массы стала `FAIL` и общий статус перешёл в `failed`.

40-модульный regression дополнительно требует:

```text
verification.failed = 0
verification levels 1..4 = PASS
verificationInternalCheckCount согласован с паспортом
```

## Solid-rod sanity-check

Для специального случая:

```text
d_rib = a/2
D_solid = 2a/sqrt(3)
A6/Asolid = 9/8 = 1.125
```

решётчатая мачта сравнивается со сплошной круглой консолью той же высоты и габарита по боковой предельной силе и линейной жёсткости. Цель — ловить ошибки порядка величин, а не требовать искусственного равенства разных конструкций.

## Web Worker и progress

FEM, eigen-buckling, специальные предельные расчёты и подбор диаметра выполняются в `site/calculation-worker.js`. Main thread обслуживает форму, progress UI, viewer и экспорт. Расчёт можно остановить через `worker.terminate()`.

## Бумажный расчётный проект

Кнопка **«Скачать расчётный проект»** формирует автономный HTML для печати/PDF. Он читает уже рассчитанный result object и не решает FEM повторно.

В документ входят:

- исходные параметры и Git SHA;
- геометрия и section properties;
- нагрузки и погода;
- frame equations и `N/V/T/M`;
- stress/Euler/global buckling;
- боковая и статическая нагрузки вершины;
- **verification passport с формулами, ожидаемыми/фактическими значениями и инструкцией «Как проверить самому»**;
- явно незакрытые external FEM/expert/physical levels;
- ограничения модели.

В бумажном проекте нет JSON. Internal `CalculationSnapshot v6` хранит полный reproducibility state, включая verification evidence, для regression/debug.

## Ограничения

Пока не реализованы:

- реальная геометрия соединительного узла и kerf/trim/overlap;
- нормативный расчёт болтов, резьбы, гаек и сварки;
- полноценные нормативные сочетания;
- geometric nonlinearity/P-Delta и initial imperfections;
- пластичность и усталость;
- параметрический фундамент;
- опубликованные результаты независимого внешнего FEM cross-check.

Поэтому internal verification — это проверка реализации сформулированной модели, а не окончательная validation реальной конструкции.

## CI/CD

PR CI включает:

```text
Syntax, policy and maintainability
Secrets scan
Tests — Ubuntu
Tests — macOS
Tests — Windows
Static site smoke test
```

Smoke проверяет Worker и browser modules, включая `verification.js`.

## Локальный запуск

```bash
python3 -m http.server 8080 --directory site
```

Открыть `http://localhost:8080/`.

Проверки:

```bash
npm test
npm run check
node scripts/check-file-line-limits.mjs
```

Runtime npm-зависимостей нет. Node.js используется для tests и CI utilities.
